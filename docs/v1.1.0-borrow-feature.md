> **最後更新**：2026-04-28

## 一、目標與範疇

### 目標

讓家庭成員可以「申請借閱」對方分享的書籍。書主收到申請後在 MooFamily 上同意，由 Content Script 自動操作讀墨原生的借書流程完成借出，將手動操作減到最低。

### Scope B（半自動化整合）

- **Content Script 自動化**：書主同意借閱後，自動在讀墨頁面開啟「詳細資訊 → 借出 → 選成員」流程
- **唯一手動步驟**：讀墨原生的 `window.confirm` 對話框需書主手動點 OK（此為瀏覽器原生對話框，無法安全地自動點擊）
- **狀態自動轉換**：借出 dialog 關閉後（MutationObserver 偵測），自動更新 status: LENT
- **歸還偵測**：依讀墨原生流程操作；MooFamily 提供「標記已歸還」按鈕做手動記錄

### 不在範圍內

- 自動偵測讀墨書庫變化（書本被借出/歸還的物理狀態變化）
- 推播通知（browser notification）— v1.1.0 僅以浮動按鈕 badge + Dialog 內 badge 通知
- 借閱請求的自動過期清理

## 二、使用者流程

### 2.1 設定階段（首次使用，延遲啟動）

第一次書主在 MooFamily 點「同意借閱」時，若該借閱者尚未設定 `readmooName`，觸發一次性設定流程：

```
書主點「同意借閱」
  ↓ readmooName 未設定？
是 → Content Script 在背景開啟讀墨「借出書籍」dialog（任一本書）
   → 抓取 dialog 中所有讀墨家庭成員清單（avatar + name）
   → MooFamily 顯示選擇 UI：「請選擇對應於 [borrowerName] 的讀墨成員」
   → 書主點選正確的讀墨成員
   → PATCH /api/family/:id/member/:uid → 儲存 readmooName
   → 自動關閉讀墨 dialog，繼續同意借閱流程
```

> 設定流程含兒童帳號的辨識（兒童帳號也會出現在讀墨借出 dialog 中，書主依 avatar/name 選正確成員）。

### 2.2 申請借閱

```
[借書方] 在「家庭書櫃」分頁瀏覽
  ↓ Hover 一本他人的書（書主 canLend=TRUE 才顯示按鈕）
  ↓ 出現「申請借閱」按鈕 → 點擊
  ↓ POST /api/family/:familyId/borrow → status: PENDING
  ↓ 切換到「借閱」分頁可見寄件匣（已申請）
```

### 2.3 通知

```
[書主側]
打開讀墨頁面
  ↓ Content Script 在 page ready 後，呼叫 GET /api/family/:familyId/borrow
  ↓ 計算 PENDING 且 ownerId === userId 的數量 N
  ↓ 若 N > 0：浮動按鈕「家庭書櫃」右上角顯示紅色 badge（數字 N）
  ↓ 開啟 Dialog → 「借閱」分頁右上也顯示同 badge
```

### 2.4 同意借閱（Scope B 自動化）

```
[書主] 借閱分頁 → 收件匣 → 點「同意借閱」
  ↓ readmooName 未設定？→ 先跑 2.1 設定流程
  ↓ Content Script 自動：
    1. 確認當前在讀墨書櫃網域（next.readmoo.com 或舊站 read.readmoo.com；否則 navigate 過去）
    2. 在 #/library 頁面找到 bookId 對應的書卡
       （遍歷 DOM、必要時換頁；找不到 → 顯示錯誤）
    3. 模擬 hover/click 開啟「詳細資訊」modal (.book-detail-modal)
    4. 在 modal 中找到 .mo-envelope 父元素「借出」→ 點擊
    5. 在「借出書籍」dialog 中比對 readmooName → 點擊對應成員
  ↓ 讀墨原生 window.confirm 出現 →【書主手動點 OK】
  ↓ MutationObserver 偵測借出 dialog 從 DOM 消失
  ↓ PATCH /api/borrow/:requestId { status: LENT }
  ↓ MooFamily UI 自動更新狀態
```

**失敗 fallback**：若任一步失敗（找不到書、找不到對應成員、讀墨改版等），顯示錯誤訊息 + 手動借出教學連結（深連結到 `next.readmoo.com/read/#/library`，舊站為 `read.readmoo.com/#/library`），status 維持 PENDING。

### 2.5 拒絕／取消／歸還

| 操作       | 操作者 | API                                           |
| ---------- | ------ | --------------------------------------------- |
| 拒絕申請   | 書主   | `PATCH /api/borrow/:id { status: REJECTED }`  |
| 取消申請   | 申請者 | `PATCH /api/borrow/:id { status: CANCELLED }` |
| 標記已歸還 | 任一方 | `PATCH /api/borrow/:id { status: RETURNED }`  |

歸還的物理操作仍由讀墨原生流程處理；MooFamily 的「標記已歸還」純為記錄。

## 三、資料模型

### 3.1 BorrowStatus Enum

```typescript
export enum BorrowStatus {
  PENDING = 0, // 申請中
  LENT = 1, // 已借出
  RETURNED = 2, // 已歸還
  REJECTED = 3, // 已拒絕
  CANCELLED = 4, // 已取消
}
```

**狀態轉移圖（FSM）**：

```
                      ┌─────────┐
   borrower POST ────▶│ PENDING │
                      └────┬────┘
            ┌──────────────┼──────────────┐
            │              │              │
   owner PATCH       owner PATCH    borrower PATCH
       LENT            REJECTED        CANCELLED
            │              │              │
            ▼              ▼              ▼
       ┌───────┐      ┌─────────┐    ┌──────────┐
       │ LENT  │      │REJECTED │    │CANCELLED │
       └───┬───┘      └─────────┘    └──────────┘
           │             (final)        (final)
   either PATCH
       RETURNED
           │
           ▼
       ┌─────────┐
       │RETURNED │
       └─────────┘
         (final)
```

REJECTED / CANCELLED / RETURNED 為終局狀態，不可再轉移。

### 3.2 BorrowRequest Schema

```typescript
export interface BorrowRequest {
  requestId: string; // UUID v4，由 server 端用 crypto.randomUUID() 產生
  familyId: string;
  borrowerId: string; // 申請者 userId
  borrowerName: string; // 申請者顯示名稱（建立時快取，不跟隨後續 displayName 變更）
  ownerId: string; // 書主 userId
  bookId: string;
  bookTitle: string;
  bookAuthor: string;
  bookCoverUrl: string;
  status: BorrowStatus;
  createdAt: string; // ISO 8601
  updatedAt: string; // ISO 8601
}
```

### 3.3 KV 新增 Key

| Key Pattern                 | Value                        | TTL |
| --------------------------- | ---------------------------- | --- |
| `borrow:{requestId}`        | `BorrowRequest`（完整 JSON） | 無  |
| `borrows:family:{familyId}` | `string[]`（requestId 陣列） | 無  |

### 3.4 FamilyMember 擴充

```typescript
export interface FamilyMember {
  userId: string;
  displayName: string;
  canLend: number; // BoolFlag，預設 BoolFlag.TRUE（1）
  readmooName?: string; // 在讀墨借出 dialog 中對應的成員名稱；undefined 表未設定
}
```

- `canLend`：家庭管理者（ownerId）可在「設定」中針對每位成員切換
- `readmooName`：由 ownerId 在 2.1 設定流程中設定；本人也可自己更新

### 3.5 normalizeFamilyRecord 向後相容

舊家庭記錄無 `canLend` / `readmooName` 欄位，`normalizeFamilyRecord` 需補上預設值：

- `canLend`：缺漏時預設 `BoolFlag.TRUE`
- `readmooName`：保持 undefined

## 四、API Contract

所有借閱端點需 Bearer token 驗證（已有 auth middleware）。

### 4.1 `POST /api/family/:id/borrow` — 發出借閱申請

```
Auth: borrower（必須是該家庭成員）

Request Body:
{
  bookId: string,
  bookTitle: string,
  bookAuthor: string,
  bookCoverUrl: string,
  ownerId: string
}

Validation:
- borrower 必須在 family.members 中
- ownerId 必須是 family.members 中的另一位（不能借自己的書）
- ownerId 對應的 FamilyMember.canLend === BoolFlag.TRUE
- borrower 自己的 FamilyMember.canLend === BoolFlag.TRUE（雙向 Readmoo family 檢查）
- 不能對同一 (borrowerId, bookId) 重複建立 PENDING（DUPLICATE_REQUEST）

Response 201: { data: BorrowRequest }

Error Codes:
- 403 NOT_FAMILY_MEMBER：borrower 非家庭成員
- 403 INVALID_OWNER：ownerId 不是另一位成員
- 403 LENDING_DISABLED：雙方任一 canLend=FALSE
- 400 DUPLICATE_REQUEST：同 borrower+book 已有 PENDING
- 404 FAMILY_NOT_FOUND
```

### 4.2 `GET /api/family/:id/borrow` — 列出家庭借閱請求

```
Auth: family member

Response 200: { data: BorrowRequest[] }

備註：
- 僅回傳呼叫者為 borrowerId 或 ownerId 的請求（含所有狀態）；同家庭但非當事人的紀錄不會出現在回應中
- 由 client 端依 borrowerId / ownerId 拆分為 incoming / outgoing
- 由 client 端依需要過濾 active vs. archived
```

### 4.3 `PATCH /api/borrow/:requestId` — 更新狀態

```
Auth: 依目標狀態而定（見下表）

Request Body:
{ status: BorrowStatus }

Response 200: { data: BorrowRequest }
Response 422: INVALID_STATUS_TRANSITION
Response 403: 操作者無權限（見下表）
Response 404: REQUEST_NOT_FOUND

權限與合法前置狀態：

| target status | 可操作方 | 合法前置狀態 |
|---------------|---------|------------|
| LENT          | ownerId | PENDING    |
| REJECTED      | ownerId | PENDING    |
| CANCELLED     | borrowerId | PENDING |
| RETURNED      | ownerId 或 borrowerId | LENT |
```

### 4.4 `PATCH /api/family/:id/member/:uid` — 更新成員設定（新增）

```
Auth:
- 更新 canLend：必須是 family.ownerId
- 更新 readmooName：必須是 family.ownerId 或 :uid 本人

Request Body:
{
  canLend?: BoolFlag,
  readmooName?: string
}

Response 200: { data: FamilyMember }
Response 403: 無權限
Response 404: MEMBER_NOT_FOUND
```

### 4.5 `DELETE /api/family/:id/member/:uid`（已有，新增 side effect）

成員移除時同步處理：

1. 從 `family.members[]` 移除該成員
2. 列出 `borrows:family:{familyId}` 中所有請求
3. 對涉及該成員（borrowerId 或 ownerId 為被移除者）且狀態為 PENDING 的請求，更新為 CANCELLED（不刪除，保留歷史）
4. LENT 狀態的請求保留現狀（書可能還借在外）

## 七、安全與隱私不變式

### 既有不變式（不可破壞）

| ID    | 不變式                       | 與借閱功能的關係                         |
| ----- | ---------------------------- | ---------------------------------------- |
| Inv 1 | 所有 user/family 端點需 auth | borrow 端點全部走 auth middleware        |
| Inv 3 | save-before-sync             | 借閱請求是即時操作（無草稿狀態），不適用 |
| Inv 4 | unbind isolation             | 成員離開時 PENDING 自動 CANCELLED        |
| Inv 5 | personal settings persist    | borrow 資料屬家庭維度，不違反            |

### 新增安全要點

- **權限隔離**：書主不能 PATCH 為 CANCELLED；借閱者不能 PATCH 為 LENT/REJECTED
- **重複申請防護**：同 (borrowerId, bookId) 至多 1 個 PENDING
- **canLend 雙向檢查**：建立請求時同時驗證雙方 canLend
- **rate limiting**：見 §五

## 十一、未盡事項（v1.2+ 考慮）

- **完全自動化的 confirm 點擊**：透過 page-injected script (`world: "MAIN"`) 攔截 `window.confirm`，需評估對讀墨其他功能的影響
- **PWA 推播通知**：透過 service worker push 即時通知書主
- **借閱請求過期**：PENDING 超過 N 天自動 CANCELLED
- **借閱統計**：書主端的歷史借出統計
- **歸還偵測**：透過下一次同步書單時，比對 LENT 書是否回到書主書庫，自動 RETURNED
