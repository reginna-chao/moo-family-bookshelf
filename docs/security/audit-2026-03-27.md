## CRITICAL 問題（必須修復）

### C1. 環境檔案已 commit 至 git（Dim 1 / Dim 7）

- **位置：** `extension/.env.development`, `extension/.env.production`
- **說明：** `.env.development` 和 `.env.production` 已被追蹤於 git 歷史中（commit `451464a`），暴露 Cloudflare Workers 子網域 `rcworkadd.workers.dev`。
- **風險：** 一旦 commit，即使後續刪除，歷史紀錄仍可被檢索。洩漏帳號識別碼。
- **修復：**
  1. 修正 `.gitignore` 加入 `.env*` 規則
  2. `git rm --cached extension/.env.development extension/.env.production`
  3. 考慮使用 `git filter-branch` 或 BFG Repo-Cleaner 清除歷史

### C2. 加密金鑰存放於 chrome.storage.sync（Dim 4）

- **位置：** `extension/src/dialog/Onboarding.tsx:77`, `extension/src/background/index.ts:13,47,56`
- **說明：** 原始加密金鑰（base62 編碼）同時存入 `chrome.storage.sync`，該儲存區會同步至 Google Cloud。
- **風險：** 金鑰安全性依賴 Google 帳號安全。若帳號遭入侵，攻擊者可取得金鑰並解密所有資料。
- **修復：**
  1. 移除所有 `chrome.storage.sync.set({ encryptionKey })` 呼叫
  2. 僅使用 `chrome.storage.local` 儲存金鑰
  3. 跨裝置同步依賴既有的 sync code 機制

### C3. API 無認證機制（Dim 6）

- **位置：** `worker/src/index.ts`（全域）, 所有 route 檔案
- **說明：** 所有 endpoint 無認證 middleware，`userId` 由 client 端直接提供，任何人可冒充任何使用者。
- **風險：** 攻擊者可代表任意使用者建立家庭、修改設定、存取他人加密資料。
- **修復：**
  1. 實作 auth middleware，透過 token 驗證身份
  2. 從已驗證的 token 中提取 userId，不接受 request 參數中的 userId

### C4. familyId 路徑參數未驗證（Dim 6）

- **位置：** `worker/src/routes/bookshelf.ts:9`, `worker/src/routes/family.ts:57,128,196,216`
- **說明：** familyId 從 URL 路徑取出後直接用於 KV key 建構（`family:${familyId}`），無格式驗證。
- **風險：** KV key injection — 攻擊者可建構惡意 familyId 存取非預期的 KV entries。
- **修復：**
  1. 建立 `isValidFamilyId()` 驗證函式（regex: `^[a-z0-9]{4}-[a-z0-9]{4}$`）
  2. 在所有使用 familyId 的 handler 加入驗證

### C5. Family bookshelf 無授權檢查（Dim 6）

- **位置：** `worker/src/routes/bookshelf.ts:8-46`, `worker/src/routes/family.ts:194-212`
- **說明：** `GET /api/family/:id/bookshelf` 和 `GET /api/family/:id/members` 無授權檢查，任何知道 familyId 的人皆可存取。
- **風險：** 家庭成員清單與加密書籍資料（含 metadata）可被未授權存取。
- **修復：**
  1. 認證後驗證呼叫者為該 family 的成員
  2. 非成員回傳 403 Forbidden

### C6. .gitignore 規則不足（Dim 7）

- **與 C1 重複** — `.gitignore` 未涵蓋 `.env.development` 和 `.env.production`。

## WARNING 問題（建議修復）

### W1. 硬編碼 Cloudflare Workers 子網域（Dim 1）

- **位置：** `extension/src/constants.ts:11`, `pwa/src/constants.ts:10`
- **說明：** 預設 API endpoint fallback 包含 `rcworkadd.workers.dev`，暴露帳號識別碼。
- **修復：** 考慮使用自訂網域取代 Workers 子網域。

### W2. 依賴套件 HIGH 漏洞（Dim 2）

- **位置：** `worker/package.json` — `@cloudflare/vitest-pool-workers` 0.5.41
- **說明：** 4 個 HIGH 等級漏洞（devalue prototype pollution、wrangler OS command injection CVE-2026-0933、undici WebSocket DoS）。皆在 devDependency 中，不影響 production bundle。
- **修復：** 升級 `@cloudflare/vitest-pool-workers` 至 `^0.13.4`。

### W3. vitest / vite 版本過舊（Dim 2）

- **位置：** 所有 `package.json`
- **說明：** vitest 2.1.9（最新 4.x）、vite 6.4.1（最新 8.x），包含 esbuild CORS 漏洞。
- **修復：** 升級至最新主版本。

### W4. base64 解碼無 try-catch（Dim 3）

- **位置：** `extension/src/crypto/encrypt.ts:156`, `pwa/src/crypto/encrypt.ts:156`
- **說明：** `atob()` 可能因格式錯誤的 base64 輸入拋出例外，無錯誤處理。
- **修復：** 加入 try-catch wrapper。

### W5. PWA 加密金鑰明文存於 localStorage（Dim 3）

- **位置：** `pwa/src/hooks/useAuth.ts:26-40`
- **說明：** 加密金鑰以明文存於 localStorage，任何同源 XSS 漏洞皆可竊取。
- **修復：** 實施嚴格 CSP 防止 XSS，考慮使用 sessionStorage。

### W6. manifest.json 缺少 CSP（Dim 4）

- **位置：** `extension/public/manifest.json`
- **說明：** 未定義 `content_security_policy`，僅依賴 MV3 預設值。
- **修復：** 加入明確的 CSP：
  ```json
  "content_security_policy": {
    "extension_pages": "default-src 'self'; script-src 'self'; object-src 'none'"
  }
  ```

### W7. web_accessible_resources 過度寬泛（Dim 4）

- **位置：** `extension/public/manifest.json:19-23`
- **說明：** `src/*` 和 `chunks/*` 暴露過多資源給 readmoo.com 頁面。
- **修復：** 僅列出實際需要的檔案。

### W8. chrome.runtime.onMessage 缺少 sender 驗證（Dim 4）

- **位置：** `extension/src/background/index.ts:38-77`
- **說明：** 未驗證 message sender 身份和來源，未處理未知 message type。
- **修復：** 驗證 `sender.tab` 和 `sender.url` 來自 readmoo.com。

### W9. production console.log 輸出敏感資料（Dim 5）

- **位置：** `extension/src/dialog/PersonalShelf.tsx:51,55,59,71,75`
- **說明：** 完整的書籍清單、API 回應被 log 至 console。
- **修復：** 移除或限制為 debug 模式。

### W10. CORS 未限制來源（Dim 6）

- **位置：** `worker/src/index.ts:15`
- **說明：** `cors()` 使用預設設定，允許所有來源。
- **修復：** 設定 origin 白名單。

### W11. Rate limiting 無差異化（Dim 6）

- **位置：** `worker/src/middleware/rateLimit.ts`
- **說明：** 所有 endpoint 統一 60 req/min。建立/加入家庭等敏感操作應更嚴格。
- **修復：** 敏感 endpoint 降至 10-20 req/min。

### W12. 缺少安全性 HTTP headers（Dim 6）

- **位置：** `worker/src/index.ts`
- **說明：** 未設定 `X-Content-Type-Options`、`X-Frame-Options`、`Strict-Transport-Security` 等。
- **修復：** 新增安全性 headers middleware。

## INFO 問題（可選改善）

### I1. Rate limiting parseInt 缺少邊界檢查（Dim 3）

- **位置：** `worker/src/middleware/rateLimit.ts:18`
- **說明：** `parseInt(current, 10)` 未處理 NaN 或 corrupted KV 資料。

### I2. KV family record 反序列化驗證不足（Dim 6）

- **位置：** `worker/src/kv/schema.ts:27-36`
- **說明：** `normalizeFamilyRecord()` 僅檢查 members 是否為空，未驗證其他欄位。

### I3. error handler 記錄完整 error 物件（Dim 6）

- **位置：** `worker/src/index.ts:34-40`
- **說明：** `console.error("Unhandled error:", err)` 可能在 production logs 中暴露內部細節。

### I4. 依賴套件 MODERATE / LOW 漏洞（Dim 2）

- **說明：** 7 個 moderate、3 個 low 漏洞，皆在 devDependency 中。包含 esbuild CORS（僅影響 dev server）和 brace-expansion DoS。

### I5. Family join 競態條件（Dim 6）

- **位置：** `worker/src/routes/family.ts:106-109`
- **說明：** KV 無 atomic compare-and-swap，並行 join 可能繞過 maxMembers 限制。程式碼中已有註解說明。

## 正面發現

- AES-256-GCM + `crypto.subtle` 實作正確，每次加密產生新 IV（12 bytes）
- 加密金鑰從未透過 API 傳送至伺服器（零知識架構）
- 無 `eval()`、`innerHTML`、`dangerouslySetInnerHTML` 等程式碼注入風險
- CI/CD 正確使用 `${{ secrets.* }}` 管理憑證
- `wrangler.toml` 使用 placeholder，不含真實 ID
- userId 輸入驗證（`isValidUserId()`）已正確實作
- 所有外部連結使用 `rel="noopener noreferrer"`
- 無 PII、無內部 URL、無真實個資出現在原始碼中
- MIT License 正確設定
