### 執行槓桿

- **E1**：git commit 一律不覆寫 `core.hooksPath`；`pnpm install` 已把 husky 設好，覆寫只會讓 hook 找不到檔案（G6）。
- **E2**：讀 vitest 輸出前先去 ANSI：`sed 's/\x1b\[[0-9;]*m//g' | grep -E "Test Files|Tests  "`；mutation check 的紅數一定要看到數字才算證據（G7）。
- **E3**：純搬移的驗證用 `git show HEAD:<file> | sed -n '/start/,/end/p'` 去縮排後 diff 新檔，比目視快且可以寫進 Fix Cycle Log；這次 7 次搬移都這樣驗。
- **E4**：預期會紅的既有測試在派 coder 前就 grep 出來（token fixture 這次 18 個），連同新預期一起寫進 tester prompt，省掉 discovery 一輪（G8）。
- **E5**：reviewer／security-auditor prompt 固定寫「不跑完整 vitest 套件」，orchestrator 在所有 agent 回來後只跑一次全套；這次四輪都沒有 CPU 爭用造成的 flake。

## 4. Skill / Agent 增減建議

- **reviewer（slim）**：這次 27 次派工有 9 次是 reviewer，其中 4 次是「測試碼 focused review」。當 tester 的回報已附完整 mutation 證據（紅數、哪些案例）時，測試碼審查可以併入下一輪 production reviewer 的 prompt（「順帶核對 tester 回報的 mutation 證據與 header 正確性」），省一次派工；只有 tester 回報沒有 mutation 證據時才單獨派。
- **coder（add 一句）**：`.claude/agents/coder.md` 在「檔案剛好在上限」的情況，允許 coder 在同一輪自行提出並執行純搬移（不是停下回報），條件是回報裡附上 `git show HEAD:` 的逐字比對證據。這次 round 1 停下是對的（prompt 寫了違規做法），但之後六次搬移都是 prompt 預先指定才做，顯示這個授權可以常態化。
- **tester（keep）**：mutation check 寫進 prompt 後，七次回報都附了紅數，focused review 幾乎沒有再找到斷言問題（只有註解措辭）。維持。
