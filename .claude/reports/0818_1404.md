## 2 卡點與摩擦

**U#（使用者更正）：無。** 兩次 AskUserQuestion 決策（bot 不回覆／做型別修正）皆一次定案。

**G1 — orchestrator 以 `git checkout --` 洗掉尚未 staged 的 coder 產出（本 run 最嚴重）**
tripwire 驗證（把 `"creating"` 改成 `"Creating"` 證明 TS2367 會擋）直接改動 working tree 的 `IdleView.tsx`，完成後用 `git checkout -- <file>` 復原——但 coder 的修改尚未 staged，index 內容是 HEAD 版本，一個指令把 agent 產出全部抹掉。復原依賴兩個僥倖：coder 報告裡有完整 diff、且 diff 標頭含 blob hash（`ad585a4..2d2d0f3`）可供重做後逐位元組比對。根因：**對 tracked 檔做丟棄式實驗前，沒有先固定基準（stage 或副本）**。

**G2 — perl in-place 編輯損壞含中文的 UTF-8 檔案**
重新套用 diff 時用 perl `-0pi` 對 `IdleView.tsx` 做替換，pattern 含 `\x{2192}`（→）觸發 wide-character 輸出，把第 42/74 行的中文字串弄出 `no-irregular-whitespace` lint 錯誤。第二次還原後改用 Edit 工具一次成功。教訓：**Windows 環境下對含 CJK 內容的檔案做內容級編輯，用 Edit 工具；sed/perl 僅限 ASCII-safe 操作**。兩次失誤合計多花約一輪驗證與兩次還原，最終產出經 blob hash 證實與 coder 原始產出逐位元組相同。

**G3 — reviewer 佔本 run 60% wall-clock（409s／總約 680s）**
其產出品質高（graph 腳本驗證 runtime cycle=0、O6 的 mock 降型護欄分析），對 PASS 結論的信心貢獻實質，此成本可接受；記錄供趨勢觀察，非提案標的。

### Flow-structural

- **L0818_1404-1** — orchestrator 對 tracked 檔案做任何丟棄式實驗（tripwire、突變測試）前，必須先固定復原基準：先 `git add` 受影響檔，或在 scratchpad 開副本操作；嚴禁對「working tree 有未 staged agent 產出」的檔案直接 mutate-then-checkout。
  `target=.claude/skills/develop/references/code-cycle.md | sketch=Phase 3 verify 段加一條 destructive-experiment 前置規則（stage-before-mutate） | status=proposed`

- **L0818_1404-2** — agent 產出被 orchestrator 接受後立即 `git add`，把 index 當作 agent 交付物的保全快照；本 run 若在 coder 回報當下就 stage，G1 整段不會發生。
  `target=.claude/skills/develop/references/code-cycle.md | sketch=Phase 3 step 2 之後加「stage accepted agent output immediately」 | status=proposed`

### 執行槓桿（E#，無流程缺口）

- **E1** — 含 CJK／非 ASCII 內容的檔案一律用 Edit 工具改內容；sed/perl 只用於純 ASCII 的機械操作。判準：pattern 或目標行含任何非 ASCII 字元即換工具。
- **E2** — 檔案互斥的 coder∥tester 平行派送在「契約可事前完整指定」時成立且高效（本 run 雙方各 ~120s 同時完成、零衝突）；成立要件是兩份 prompt 都載明對方會造成的預期紅字，避免互相「修好」對方的半成品。
- **E3** — 型別收緊類變更的驗證，除了全綠之外加一個「反向 tripwire」（故意打錯字證明會編譯失敗），把「洞封住了」從推論變成實證；成本一次 tsc。
