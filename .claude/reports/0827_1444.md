## 2 卡點與摩擦

- **G1 權限 classifier 對 `.claude/` 寫入的攔截不可預測**：同性質檔案有的放行（`skills/develop/` 主檔、`rules/change-triage.md`）、有的拒絕（`references/retro.md`、`distill/SKILL.md`；`rules/global.md` 對 subagent 拒、對主 session 放行）。後果：一輪 dispatch 只完成 1/4，兩處措辭同步至今 pending 使用者手動套用。證據：兩次 DENIED 紀錄。
- **G2 `origin/main` 於 run 中前進**：worktrees 共用 refs，其他 session 的 fetch 即全域生效，`git diff origin/main` 突然混入他人 commit（#139）；接著 ff-merge 又被行尾正規化的 stat-dirty 檔擋下（需先 `git restore` 七個零內容差異檔）。教訓已直接固化為規則：fix mode 條件 3 改以 merge-base 量測（S4）。
- **G3 全 repo `pnpm format` 不可用作 verify**：此環境超時（>2min），且把 ~250 個 CRLF 檔改寫為 LF（內容零差異、`git status` 大量噪音、間接引發 G2 的 merge 阻擋）。改用 targeted `pnpm exec prettier --write <files>` 後無此問題。
- **G4 桌面程序中斷**：一個進行中 agent 無完成紀錄（實際編輯已落地，重啟後以磁碟狀態核對即可），並切斷未送出的 AskUserQuestion，恢復後需重發決策問題。
- **U**：無 verbatim 修正。三次決策皆採 TL 建議；O1（backend fix mode 實質不可達）由使用者選擇「接受＋開 issue 追蹤」。
