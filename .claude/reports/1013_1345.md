## 2. 卡點與摩擦

- **G1**：backend reviewer 第 1 輪發現儲存位置的設計問題（`user:{id}` 欄位會被別台裝置的整份 PUT 蓋回），使用者改採獨立 key；當時 backend tester 第 1 輪已在跑，測試寫到一半設計換掉。tester 自行偵測到 staged 變更並改寫成新設計，但這是運氣。證據：tester 回報開頭「Worker 設計在我執行途中換掉了」。
- **G2**：frontend reviewer 第 1 輪抓到 P0：沒配對到的換 id（書名重複）會被當新書自動開放。需求分析和 coder 規格只排除了「配對成功的換號目標」，沒有鏡像 `deferRenameCandidates` 的「同名已存書」規則。證據：reviewer 實跑 60 本、2 本同名刻意不分享的書 → 2 本都變成開放。
- **G3**：`docs/architecture.md` 由 frontend coder 擁有，但 backend 設計改了兩次，每次都要 orchestrator 自己回頭改 API／KV 段落（三次），再由 reviewer 指出遺漏。證據：Fix Cycle Log 中三次「文件改獨立 key」。
- **G4**：frontend tester 跑變異測試時建的暫存檔讓 orchestrator 同時跑的 `pnpm lint` 出現 ENOENT，誤判為 lint 紅。證據：lint log 只有一行 `ENOENT … __mutation__/mutatedAutoShare.ts`。
- **G5**：session 在 commit gate 的 AskUserQuestion 中斷，回答遺失；因為所有變更都已 staged、PR 內文已寫到 scratchpad，重啟後只需再問一次。
- **G6**：安全掃描找到的 WARNING（被移除後再同步回來的書會被自動開放）是兩個功能（#241 移除、#238 自動開放）疊加後才出現的風險，兩邊各自的審查都看不到。證據：auditor 報告維度 8 的觸發情境。

## 3. 改進提案

### Flow-structural

- **L1013_1345-1** `target=.claude/skills/develop/references/code-cycle.md | sketch=Phase 3 第 4 點補一句：backend 的 reviewer 先於 backend 的 tester 派出（或至少同時），review 若動到 KV schema／契約，tester 的工作會整批作廢；frontend 亦同 | status=proposed`（對應 G1）
- **L1013_1345-2** `target=.claude/skills/develop/references/code-cycle.md | sketch=Phase 1 第 6 點補一句：任何「自動設定分享旗標」或「依快照刪除」的功能，需求分析要逐條列出 renamedBooks／legacyBooks／deferRenameCandidates／pruneBooks 的規則並說明各自如何鏡像，寫進 coder 提示 | status=proposed`（對應 G2；與 #241 retro 的 L5 同方向）
- **L1013_1345-3** `target=.claude/skills/develop/SKILL.md | sketch=§3 平行派工補一句：docs/architecture.md 這類跨 scope 的檔案，在兩邊 coder 都完成後，由最後一輪的 coder（或 orchestrator）做一次「對帳 pass」，不在第一輪就分給單一 scope 的 coder | status=proposed`（對應 G3）
- **L1013_1345-4** `target=.claude/agents/security-auditor.md | sketch=invariants 維度加一項：新功能若改變「書何時被設為分享」或「書何時被移除」，要檢查它與既有的移除／換號／自動開放步驟疊加後的情境 | status=proposed`（對應 G6）

### 執行槓桿

- **E1**：tester 在跑時不要同時跑該套件的 lint（變異測試的暫存檔會造成 ENOENT 假紅）；lint 留到 tester 回報後。
- **E2**：把 PR 內文、issue 內文先寫進 scratchpad 檔案再用 `--body-file`，session 中斷時不用重寫；這次重啟後直接可用。
- **E3**：全端 run 的三個套件由 orchestrator 依序跑一次（Worker → extension → PWA），不交給各 tester 各跑一次全套；兩個 tester 各自跑全套時都遇到另一邊的設計變更。
- **E4**：安全 WARNING 的處置用一個 AskUserQuestion 連同 re-review 的 SUGGESTION 一起問，省一次 stop。

## 4. Skill / Agent 增減建議

- **tester**：回傳格式加一條「開始時記下 staged 的 HEAD／diff hash，結束前比對；不同就在回報開頭標明」——這次 backend tester 是自己注意到的，應該變成規定。
- **reviewer**：維持。frontend reviewer 用 probe 腳本實跑重現 P0，是這次最有價值的發現；可在 reviewer.md 鼓勵「對純函式的邊界用腳本實跑，不只讀」。
- 不新增 agent。
