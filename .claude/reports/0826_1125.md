## 2. 卡點與摩擦

- **U1**：首個 coder 派遣前使用者中斷 tool call，隨後「請繼續完成任務」——無內容修正，純節奏確認。無流程損失。
- **G1（工作樹已含完成品）**：worktree 開場即帶著前一 session 的完整實作（未提交）。coder #1 花約 74k tokens 才確認「已完成、僅需核對」。派遣前一次 `git diff --stat` 對照任務規格即可預知，prompt 可直接改為 audit-only。
- **G2（基底移動 + 測試檔衝突）**：run 中 `origin/main` 前進 2 commits（#136/#137），#137 與本任務同檔。以 stash → ff → pop 同步，1 個測試檔尾端 append-append 衝突由 orchestrator 機械解決。tester #1 有預警，處理順暢——preflight 已 fetch，屬不可避免的時窗問題。
- **G3（agent 中途死亡）**：security-auditor 首派因 API session limit 中斷（~93k tokens 沉沒），依「fresh re-dispatch」規則重派成功。規則有效，成本無法回收。
- **G4（行為變更打破既有測試前提）**：INFO-2 修正讓 `RATE_LIMITED` 走在地化文案後，既有 sibling 測試（mock 即用 RATE_LIMITED code 驗證「伺服器訊息原樣顯示」）前提失效 → 全套件 1 紅 → SendMessage 續派 tester 修正（code 改 SERVER_ERROR）。該測試的 mock 內容在前一輪 tester 回報中可見，派遣時可預先列為 expected-red。
