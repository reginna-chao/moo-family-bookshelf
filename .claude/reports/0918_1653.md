## 2. 卡點與摩擦

**U（使用者修正）**：無。

**G1（issue #199 的 remediation 沒寫到 Dependabot 與 review bot 的交互）**：開 Dependabot 之後，它的 PR 會觸發
`claude-code-review.yml`，但 Dependabot 事件讀不到 Actions secrets（實測 Dependabot secret store 為空）且
token 強制唯讀，review job 必在模型呼叫前紅叉，每週一次。reviewer 與 auditor 各自獨立抓到。修法一行
`user.login != 'dependabot[bot]'` + 一條斷言。**新增一個自動開 PR 的 bot 時，要先過一遍「哪些 workflow
會被這種 PR 觸發、它拿得到什麼」**。

**G2（annotated tag 要解引用）**：`pnpm/action-setup` 與 `anthropics/claude-code-action` 的 tag 是 annotated，
`git/ref/tags/<tag>` 回的是 tag object 的 sha，直接寫進 `uses:` 會 checkout 失敗。coder 依 brief 走了
`git/tags/<sha>` → `.object.sha` 並用 `commits/<sha>` 確認。這次沒踩到，記下來是因為 brief 若沒明寫，
很容易釘錯物件。

**G3（三個 SHA 與預設分支 `diverged`，auditor 追到底才確認乾淨）**：`actions/checkout` v5.1.0 / v6.1.0 與
`dorny/paths-filter` v3.0.4 都不在 default branch 上，而是各自 `releases/vN` 分支的 HEAD，backport commit
有簽章、有正式 release。這是 actions 的標準發版模式，但如果 auditor 只看 `compare` 的狀態就會誤判。
**「commit 存在」不等於「commit 在可信分支上」，兩者都要查，diverged 要追到分支名。**

**G4（CI 可達性缺口連續兩輪各補一次）**：R1 tester 指出 `worker` filter 只列 `cicd.yml`，改兩個 Claude
workflow 不會跑 tripwire → 補 `.github/workflows/**`；R2 reviewer 指出 `dependabot.yml` 也不在 filter →
再補一行。與 `0918_1133` 的 G4、`0918_0957` 的 tester 發現同一模式：**每新增一支讀 repo 檔案的 tripwire，
它讀的每個路徑都要出現在該 job 的 filter 裡**，這件事應該在 tester 的 brief 裡就要求列出「本測試讀取的
路徑清單」並對照 filter，而不是靠 reviewer 事後抓。

**G5（`.github/workflows/**` 進 `worker` filter 的副作用）**：`deploy-worker-dev` 也吃這個 filter，所以只改
Claude workflow 併入 main 會多跑一次 dev Worker 的 no-op 部署。auditor 標 INFO，接受；記錄是因為 filter
同時當「跑檢查」與「跑部署」的閘門，這個耦合不明顯。

**G6（測試檔算 area → `full` scan，第四次）**：與前三份報告相同。這次 `full` 的實際有效內容仍只有 Dim 1 / 7。

**G7（契約式平行派工第三次成功）**：tester 對「coder 將產出的 yml 形狀」寫斷言、在 fixture 上做 mutation，
coder 落地後真檔自然轉綠，兩輪都是。

### 執行槓桿（no flow gap）

- **E1**：釘 action SHA 的 brief 一定寫「annotated tag 解引用到 commit、用 `commits/<sha>` 確認、與移動的
  major tag 比對」三步；解析腳本存檔以便複現。
- **E2**：核對 SHA 可信度時，`compare` 回 `diverged` 要追到分支名與 release，不能只看狀態。
- **E3**：新增 Dependabot 之類的 bot 前，先 `gh api repos/:o/:r/dependabot/secrets` 看 secret store，再列出
  會被觸發的 workflow。
- **E4**：`actionlint` 在此環境無 npm bin；以 prettier 的 YAML parse + tripwire 替代，不要再試 `npx actionlint`。
- **E5**：Dependabot 第一批 PR 很可能包含 `cicd.yml` 的 checkout v5 → v6（跨 major），那是人工判斷的升級，
  不是純 SHA 搬動；合併前看清楚。
