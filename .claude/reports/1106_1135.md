## 2. 卡點與摩擦

- **U1**：「456 已合併，請重新分析」。我的範圍問題建立在 #456 還沒 commit 的狀態上，使用者回答時它已合併。問範圍前只讀了對方的計畫，等待回覆的這段時間基準就變了。
- **G1**：計畫照著外部來源的修法方向，加了一道目前走不到的守衛。金魚指出它防的是計畫自己寫「沒有可達路徑」的情境，而且要守住還得再處理共用的 refresh。拿掉後少改一個檔案、少兩個測試，也少一次安全敏感路徑。
- **G2**：CHANGELOG 第一則改了三次。第一版把範圍寫成只限自架（金魚 CD-G4、IR-G3）；第二版和已接受的行為矛盾（重審 R2-G1）；第三版仍多承諾，reviewer 與安全掃描找到另一條不經過這次修正的路徑。每次都是先寫結論，才去查所有會造成該效果的呼叫點。
- **G3**：計畫的行號有誤（金魚 CD-G1、CD-G2 列為 Blocker）。`useAutoAcquireToken.ts` 的行號是憑印象寫的，Extension 的引用則是從另一條 run 的舊計畫抄來的，它合併後行號已經移動。
- **G4**：`reviewer`、`tester`、`security-auditor` 型別在 run 中途從 registry 消失。`SKILL.md` §3 的備案可用，三個都改用 `general-purpose` 讀角色檔，流程沒有中斷。
- **G5**：`change-triage.md` 的 P0／P1 流程只有公開 issue，公開 repo 中尚未修好的安全問題要靠個人記憶才知道走私密管道；`.claude/runs/` 也沒被 ignore，commit 關卡的「保留」選項對這類 run 不安全。

## 3. 改進提案

- **L1106_1135-1**：`target=.claude/rules/change-triage.md | sketch=an exploitable, unfixed security finding in this public repo is recorded privately instead of as a public issue, and PR bodies, CHANGELOG, commits, comments and retro reports describe only the behaviour that now holds | status=proposed`
- **L1106_1135-2**：`target=.claude/skills/develop/references/code-cycle.md | sketch=Phase 8: for an undisclosed security run, withhold the "keep the run folder" option, since .claude/runs is not ignored | status=proposed`
- **L1106_1135-3**：`target=.claude/skills/develop/references/code-cycle.md | sketch=plan completeness self-check: a negative claim in user-facing copy ("never does X") greps every caller of X first and states which it covers | status=proposed`
- **不提升**：agent 型別消失。`SKILL.md` §3 已有備案，這次照著做就夠了。

**執行槓桿**

- **E1**：問「要不要等另一條 run」之前先 `git fetch`，等待回覆後也再查一次；另一條 run 的計畫只是線索，要看它實際進 `main` 的內容。
- **E2**：計畫裡的行號只寫這個 session 剛讀過的；從別的計畫抄來的先重新 grep。
- **E3**：外部來源提出的修法方向，先問「少了它，目標路徑還走得到嗎」，再決定要不要列進工作項。
