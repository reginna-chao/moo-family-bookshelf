## 2. 卡點與摩擦

沒有使用者糾正（U# 為 0）。

- **G1 — 模式沒有在開頭宣告。** `code-cycle.md` 要求在 Phase 0 之前先對四個條件做預測並記錄；這次直接派了 coder，等 coder 回來實測 54 行才第一次提到「走完整流程」。結果沒有走錯路（完整流程本來就是預設），但使用者在開頭看不到這次會跑哪一種流程，也沒有 fix mode 該有的根因重述。新增一個 37 行的檔案加上兩個呼叫點，開頭就估得出會超過 40 行。
- **G2 — verify-before-test 關卡只有問題，沒有說明。** 關卡用 AskUserQuestion 發出，題目寫「與下方說明的行為是否正確」，但那一輪沒有輸出任何說明文字：沒有變更摘要、沒有手動驗證步驟、沒有 Stop Block。使用者是只憑三個選項的描述按下確認的。`SKILL.md` §2 把這種停法列為缺陷。
- **G3 — issue 引用的檔案不在 main 上。** #272 內文說 #271 的修正已經在 `extension/src/dialog/familyBindingReset.ts` 清掉快取；Phase 0 的前提檢查用 grep 和 `gh issue view 271` 查出 #271 還是 open、檔案不存在，所以 coder 的指示沒有依賴它。這一條是規則有發揮作用，不是摩擦，記下來是因為它決定了修法（擁有者比對，而不是在既有的清除函式裡加一行）。
- **G4 — TodoWrite 不在這個 session 的工具清單裡。** 依 `SKILL.md` §1 的備援改成在 Stop Block 裡列進度，但第一份進度清單要到三個 agent 派出後才出現。
