## 2. 卡點與摩擦

使用者糾正（U#）：

- **U1 —「抱歉我換錯資料夾」。** run 是在另一個 repo 的 session 裡用 `/develop` 啟動的，載入的是那個 repo 的 `develop` skill。使用者把工作目錄切過來之後，Skill 工具回覆「已載入、內容不變」，沒有換成本 repo 的版本；orchestrator 改用 Read 直接讀 `.claude/skills/develop/SKILL.md` 和 `references/code-cycle.md` 才接上流程。這是工具行為，不是本 repo 流程的缺口。
- **U2 —「這是在哪個 worktree 進行?」。** Phase 0 的訊息只寫了「分支已從 `origin/main` 切出」，沒有說是在主要 checkout 上切的，也沒有說主要 checkout 因此離開了 `main`。使用者要另外問一次才知道。

Gate 與重工（G#）：

- **G1 — Phase 0 把共用 checkout 上另一個 session 的分支切走。** `git reflog` 為證：11:56:09 另一個 session（#256）在主要 checkout 建立 `fix/pwa-stable-api-client`，11:56:23 本 run 執行 `git checkout -b fix/sync-overwrites-mid-sync-save origin/main`，把同一個 checkout 切走。本 run 檢查「目前在 `main`、工作區乾淨」是在幾分鐘前做的，切分支的那個指令本身沒有再確認當下的分支，輸出又被 `tail -1` 截掉，所以沒有看到「moving from fix/pwa-stable-api-client」。另一個 session 的 coder、tester 因此在本 run 的分支上跑了一段時間，最後自己搬到 worktree（見 `.claude/reports/1002_1303.md` 的 G1）。本 run 直到寫這份報告、讀到那份報告才發現。
- **G2 — S1 的不精確用詞出自 orchestrator 自己的規格。** 派給後端 coder 的契約寫「400 在任何 KV 讀取之前判斷」「409 不寫入任何東西」，但 `put-books` 的每小時計數本身就是一次 KV 讀加一次 KV 寫。coder 照抄進 `docs/architecture.md`、`.claude/rules/backend.md` 和 OpenAPI 描述，後端 reviewer 抓到，多一個 coder dispatch（133 秒）修三處文字。
- **G3 — 後端 tester 三個動作被權限機制擋下。** `pnpm lint`、`prettier --write`、暫時改正式碼做變異檢查都被擋。前端 tester 遇到同樣情況後自己改用「複製一份來改」完成變異檢查；後端 tester 則停下來回報，變異檢查要等使用者同意後再派一輪（156 秒）才補上。`.claude/rules/test.md:64` 把「暫時關掉防護」和「複製一份」並列，沒有說哪個是預設。
- **G4 — 測試程式碼一開始沒有經過 reviewer。** tester 和 reviewer 平行派出，reviewer 的指示寫「進行中的測試檔不在這次審查範圍」，結果約一千行測試沒人審。orchestrator 在 commit gate 之後、寫 retro 前自我檢查才發現，補派兩個只看測試檔的 reviewer（184 秒、490 秒）。後端通過；前端回報三項不阻擋的測試品質建議（兩個不可能失敗的負向斷言、少一個「重試那次遇到非衝突錯誤」的案例、一行指向舊檔案的同步註解），依 `change-triage.md` 屬 P2，這個 run 沒有處理。補審發生在 commit gate 之後，使用者已經選了 commit 方式，這些建議沒有機會進 SUGGESTION 決策。`.claude/reports/1002_1303.md` 的 G10 是同一件事。
- **G5 — `origin/main` 在 run 中途前進，而且和未 commit 的暫存變更撞在 `CHANGELOG.md`。** #260 在同一個位置加了一則。本 run 全程沒有 commit（15 個檔都只是暫存），`git merge --ff-only` 會因為 `CHANGELOG.md` 重疊而拒絕。做法是：把暫存差異存成 patch 備份、還原 `CHANGELOG.md`、快轉、由 orchestrator 用 Edit 把同一則接在 #260 那則後面、再重跑完整驗證。`code-cycle.md` Phase 8 第 4 步只寫「rebase/ff」，沒有涵蓋「整個 run 都還沒 commit」的情況，也沒有說重疊的 CHANGELOG 由誰重新套用。commit 前 #261 又合併進來，這次撞在 `CHANGELOG.md` 和 `extension/eslint.config.js`（兩邊各改了行數上限表的不同行），同樣的步驟再做一次、完整驗證再跑一次。三個 run 同時在跑、每個都往 `## 未釋出` 的同一個位置加一則，這種重疊是必然的。
- **G6 — 安全掃描拿到的 base 指令是會移動的 `origin/main`。** prompt 裡寫了 merge-base 的 sha，但給的指令是 `git diff --cached origin/main`。`origin/main` 前進後這個指令列出 21 個檔，auditor 自己改用 merge-base 才對上 15 個檔。
- **G7 — verify-before-test gate 對競態條件幫助有限。** 時間窗只有幾百毫秒，使用者無法手動重現。orchestrator 改成在本機起 `wrangler dev`、用 curl 跑 11 個步驟，把 409／400／不帶欄位的實際回應列成表給使用者；Extension 的重試只能說明「交給測試釘住」。使用者直接回「確認正確」。
- **G8 — 行數上限決定了 API client 的寫法。** `extension/src/api/client.ts` 剛好是 866/866 行，加第三個參數會超過上限，coder 改成放寬 `data` 的型別。`extension/src/sync/syncBooks.ts` 也在上限，新邏輯一開始就指定放新檔，沒有重工。

## 3. 改進提案

Flow-structural：

- **L1002_1440-1** `target=.claude/skills/develop/references/code-cycle.md`（Phase 0）| `sketch=切分支的同一個指令裡先印出當下分支；不是 main（或使用者指定的 base）就停下來問，不切走別人的分支；開場訊息寫明是主要 checkout 還是 worktree、主要 checkout 是否離開 main` | `status=proposed`（對應 G1、U2；`1002_1303.md` 的 G1 是同一事件的另一面）
- **L1002_1440-2** `target=.claude/skills/develop/references/code-cycle.md`（Phase 3 step 4）| `sketch=tester 與 reviewer 平行時，測試檔由 tester 回來後的第二個 reviewer dispatch 審查，或改成 tester 回來後再派 reviewer；不能靠「hold findings」一句話` | `status=proposed`（對應 G4；`1002_1303.md` 的 G10 重複出現）
- **L1002_1440-3** `target=.claude/rules/test.md`（Anti-Drift → Guard tests must prove they can fail）| `sketch=變異檢查預設用副本，不就地改正式碼；刪掉「暫時關掉防護」這個選項` | `status=proposed`（對應 G3；`1002_1303.md` 的 G9 是就地改造成的另一個問題）
- **L1002_1440-4** `target=.claude/skills/develop/references/code-cycle.md`（Phase 8 step 4）| `sketch=補上「run 尚未 commit 時 main 前進」的做法：備份暫存差異、挪開重疊檔、快轉、重新套用、重跑驗證；CHANGELOG 重疊的重新套用算機械動作，orchestrator 可以做` | `status=proposed`（對應 G5）
- **U1**：不提升：Skill 工具在工作目錄切換後沒有換成新 repo 的 skill，屬於工具行為，repo 內沒有可以改的檔案。

執行槓桿：

- **E1** 契約裡寫順序時，點名是哪幾個讀寫（`user:{id}`、`member:{id}`、計數器），不寫「任何 KV」「不寫入任何東西」這種全稱句。（G2）
- **E2** 給 reviewer / auditor 的 base 一律給 merge-base 的 sha 和可以直接貼上的指令，不給分支名。（G6）
- **E3** 競態、時間窗這類手動無法重現的修正，verify-before-test gate 直接由 orchestrator 實測可測的那一端並列出觀察到的回應，另一端明說由測試釘住。（G7）
- **E4** agent 回來時不必每次都發一則完整進度訊息；同一輪平行派出的 agent 等到齊再整理一次。這次同一輪四個 agent 發了四則。

## 4. Skill / Agent 增減建議

- **tester agent**：被權限擋下時，前端 tester 自己找到規則允許的替代做法，後端 tester 停下來回報。兩者都合理，但結果差一輪。若採用 L1002_1440-3，這個差異會消失，不需要另外改 agent 定義。
- **`.claude/rules/backend.md`**：讀任何 `worker/` 檔案時整份載入，其中 API Design 的單一條目動輒上千字。這次又加了一條。這份檔案是 orchestrator context 的最大單一來源，值得在 `/distill` 時考慮把已經穩定的長條目搬進 `docs/architecture.md`、規則檔只留結論。
- 沒有需要新增或移除的 skill。
