## 2. 卡點與摩擦

**U1（使用者提問即修正）**：「另外我之前有說要導入這個 skill 嗎？」
查證後確認 repo 全文、git log、`~/.claude/skills/`、memory 都無紀錄。若當初假設「應該有提過」
直接安裝，會建立一條不存在的前提。問題本身無摩擦，但它證明**「使用者問『我之前有說過嗎』
時必須實查四處來源」**這件事值得固定下來。

**G1（自己造成的 rework，最嚴重）**：第二次重寫 CHANGELOG 時重用了第一次的
`sed -n '79,$p' CHANGELOG.md`，但檔案已被第一次重寫改過、行號位移，導致 `## v1.6.1` 整節
（兩個 `###` 小節、兩條 bullet）被靜默切掉。發現方式是重寫後肉眼掃檔案尾端，不是任何檢查抓到的。
補救：從 `git show origin/main:CHANGELOG.md` 取回原文，並改用
`diff <(git show origin/main:CHANGELOG.md | sed -n '/^## v1.6.1/,$p') <(...)` 驗證「未觸及的
區段逐字未動」。**行號式檔案切割在已修改的檔案上重用是 data loss 級別的坑**，而 prettier 與
EOL 檢查都不會發現——被刪掉的內容格式完全正確。

**G2**：`.claude/rules/user-facing-copy.md` 原本禁用詞表已完整涵蓋 1.7.0 的所有用詞，
CHANGELOG 卻仍難讀。也就是**既有規則對「用詞合規但深度失控」這一類問題完全無感**——
7 條子 bullet 描述 0.6 秒防抖與 TOML 區塊名，每個字都通過檢查。規則的檢查維度少了一個。

**G3**：試讀 agent 指出兩處「叫使用者做事卻沒說怎麼做」（兩個 `**請更新擴充功能／PWA**`）。
這兩條在原文存在已久，通過過 review 也通過過 `/bump-ver`，但沒有任何一關會問
「這個指令讀者做得到嗎」。

### 執行槓桿（無流程缺口）

- **E0916_1722-1**：使用者問「我之前有說過 X 嗎」時，固定查四處再回答——repo 全文 grep、
  `git log --all --grep`、memory 目錄、以及 skill／設定的實際安裝位置。本 run 四處都查了，
  耗時不到一次工具呼叫，卻直接否定了一個錯誤前提。

- **E0916_1722-2**：改寫使用者可見文案時，用兩個平行的 agent 取代自我檢查——一個做事實保全
  稽核（逐項比對舊文事實、去原始碼驗證、分類 LOST-CRITICAL／MOVED／DROPPED-OK），一個扮演
  目標讀者逐條試讀。本 run 稽核抓到 4 項我自己讀三遍都沒發現的事實錯誤（其中「書封改述成

- **E0916_1722-3**：vendored 第三方檔案進 repo 時，同一次 commit 就要加 `.prettierignore`
  與一份 `VENDORED.md`（upstream URL、commit sha、版本、取捨了哪些檔、更新步驟）。
  本 run 若漏掉，下一次 `pnpm format` 會把 8 個檔案改到與上游不一致，之後再也無法用覆蓋更新。
