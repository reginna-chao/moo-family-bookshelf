## 2. 卡點與摩擦

使用者糾正（U#）：無。

- **G1 — 共用 checkout 被另一個 session 切走分支。** 本 run 在 11:56:09 建立 `fix/pwa-stable-api-client`，11:56:23 同一個 checkout 被「Issue #249 解決」session 切到 `fix/sync-overwrites-mid-sync-save`（`git reflog` 為證）。orchestrator 沒有自己發現，是 tester 約 6 分鐘後在 Open Questions 提出、reviewer 的 O5 再提一次。期間 coder、tester、兩次完整測試都跑在別人的分支上。因為兩個分支都停在同一個 commit 且都沒有 commit，沒有造成污染。commit gate 多了一題分支處理，最後用「存 patch → 開 worktree 套用 → 在共用 checkout 反向套用」搬走，另外要在 worktree 重跑 `pnpm install` 才能過 husky。
- **G2 — `gh` 前兩次呼叫白費。** 第一次把 `GH_CONFIG_DIR` 覆寫成猜的路徑（`~/.config/gh-personal`）而失敗；第二次把 `gh` 和 `git` 串在同一個 PowerShell 指令裡，沒有任何輸出。讀了 memory 才拿到正確路徑。
- **G3 — `pwa/src/App.tsx` 剛好卡在 `max-lines` 上限 415 行。** 修正需要淨增 2 行，coder 只好把 `useLayoutEffect` 另開一行 import，並收掉 `acquireNewToken` 裡一個和修正無關的 `if` 來換行數。沒有多一輪往返，但檔案現在有兩行 `react` import，而且下一個要改這個檔案的 run（#258）會遇到同樣的限制。
- **G4 — issue 建議的失敗測試不適用於實際修法。** #256 建議在 hook 層換 `apiClient` prop 來測，但修正落在 App 層，那個測試修正後仍會是紅的。這點在派 tester 前就寫進 prompt，沒有重工。`pwa/tests/component/App.test.tsx` 把 `PersonalShelfPage` 整個 mock 掉，所以回歸測試只能驗「同一個物件、帶著新 token」，沒有驗到待儲存標記本身。
- **G5 — fix mode 的開場陳述晚了。** 根因與驗收條件是在 coder 回報之後才呈現給使用者，不是在 run 一開始。
- **G6 — tester 和 reviewer 平行派出。** fix-mode flow 寫的是先 tester 再 reviewer；這次比照 Phase 3 step 4 平行派出，並要求 reviewer 不跑完整測試。沒有出問題，但這是流程文字沒有明講的做法。
