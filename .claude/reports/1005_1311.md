## 2. 卡點與摩擦

- **U1**：verify-before-test 關卡期間，使用者連續提出兩個與 #266 無關的問題（「要去哪裡可以重新看到這個限制名單？」、「我用原本的視窗登入 A 帳號，用無痕視窗登入 B 帳號，結果開啟家庭書櫃顯示 A 帳號的家庭書櫃」）。兩題都查了程式碼、各開一個 issue，沒有併入本 run。關卡本身沒有退回，但中間隔了三輪對話才回到驗證。
- **U2**：關卡的回覆先是「行為正確」，派工途中被中斷，改成「不方便實機測，直接往下」。兩者結果相同（往下走），但驗收依據不同；最後以測試作為驗收，完成報告有明講。
- **G1（orchestrator 自審）**：coder 第一版在 `isLiveSession` 檢查與 `logout()` 之間插了 `await markReauthPending`，等於重開 #258。派工 prompt 沒有提醒這條時序，是進關卡前讀 diff 才發現，多一次 coder 派工。
- **G2（CRITICAL，只有 reviewer 抓到）**：`useAuth.ts` 新增的 import 讓 `constants.ts` 的 `import.meta.env` 進到 Node 端 Playwright helper，PWA E2E 全部載入失敗。typecheck、lint、vitest、E2E typecheck 全綠，code-cycle 的 E2E Impact Check（只跑 `tsc`）抓不到；reviewer 是實跑 `playwright test --list` 才看到。
- **G3**：tester 被權限分類器擋下三件事：暫時改 production 做突變檢查、`prettier --write`、`prettier --check`。三件都由 orchestrator 代跑（突變 4 組、prettier 1 次）。
- **G4**：安全掃描的 I1（共用裝置上別人登入會清掉標記）在 S1 的 tester 已派出後才回來，I1 只能另開一輪 coder → tester，沒能和 S1 併成一輪。
- **G5**：run 進行中 `origin/main` 合併了 #269，唯一重疊是 `CHANGELOG.md`（兩邊都在 `### 問題修正` 最後加一條）。變更尚未 commit，改用「取出 CHANGELOG patch → ff → 3way 套回 → 手動保留兩條」處理。
- **G6**：需求分析時 `gh issue view` 第一次用 `$HOME/.config/gh-personal` 失敗，讀了 `.claude/settings.local.json` 才拿到正確的 `GH_CONFIG_DIR`（Bash 工具不會自動帶 settings 的 env）。

### 執行槓桿

- **E1**：派 coder 改 `acquireNewToken` 這類有時序保證的函式時，prompt 直接寫明「哪兩行之間不可出現 await」，不要等讀 diff 才發現。
