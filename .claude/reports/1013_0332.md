## 2. 卡點與摩擦

- **U1**：使用者回覆「對，是 #241 請問要提供甚麼給你，一樣在 console 輸入 function 嗎?」。證據：要使用者跑的驗證腳本放在一則長訊息的上半段，下半段才是 Stop Block；接著 Explore agent 的回報又插進來，使用者沒看到腳本，多花一輪。
- **G1**：#253 的 issue 內文裡，驗證腳本的所有引號都不見了（`querySelector(.library-item)`），直接貼會語法錯誤。證據：`gh issue view 253` 的 body。原因是建立 issue 時用 `--body` 經過 shell，引號被吃掉；這次在對話裡重新給了修正版。
- **G2**：coder 第 1 輪 Fix 的「Expected red tests」漏了 `pruneBooks.test.ts` 上限表「3 本、3 個候選」那列（`kept` 為空，S1 的空擷取規則會改走 no-op、不再有警告）。證據：orchestrator 自己 grep 測試檔的 `scrapedIds` 用法才發現，tester 提示裡補上後一次改好。
- **G3**：主線在 run 中途前進兩次，兩次都和 `CHANGELOG.md` 衝突（雙方都在 `## 未釋出` 加 bullet）。證據：兩次 WIP commit → rebase → 手動排列 bullet → `reset --soft`。每次約 2 分鐘，流程本身運作正常。
- **G4**：測試檔 `PersonalShelf.test.tsx` 的 rebase 衝突只是 import 區塊（上游加一個常數、本輪換一個 import），規則寫「測試衝突交給 tester」，但派一個 agent 解 6 行機械合併不划算，orchestrator 自己解了並記入 Fix Cycle Log。
- **G5**：「借出中的書是否留在 `itemList`」無法驗證，因為使用者帳號沒有借出中的書；需求分析階段才發現這個帳號條件。證據：`mooCheckLists()` 的 `loanedLibraryItems: 0`。
- **G6**：verify-before-test 閘門沒有可以實際重現「移除」的手動路徑（需要伺服器有、讀墨沒有的書），使用者只能選擇跳過。
