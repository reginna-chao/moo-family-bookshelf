## 2. 卡點與摩擦

- **U1**：verify-before-test gate 的 AskUserQuestion 未獲回應（使用者離開）。因設計方案 (a) 已在前一輪 AskUserQuestion 逐項核准、且 orchestrator 已自驗 diff 與規格 1:1，依自主原則續行並明示「隨時可喊停折返」——後續使用者回來繼續決策,未提出異議。與 retro 0812_1356 的 U1（使用者在看、期望 gate）並不矛盾：差別在**規格是否已被精確核准過**。
- **G1**：auditor 的高價值發現模式——不只審新程式碼,而是審**新程式碼的信任基礎**（guard 以 record 為真實來源 → 追問「record 本身可靠嗎」→ 挖出既有 `user:{id}` lost-update 可回滾撤銷、復活已刪快照）。這個 WARNING 不是本次 diff 的缺陷,卻直接反證了我在 CHANGELOG 寫下的絕對化宣稱。
- **G2**：措辭誇大第三度在審計被抓（「不再有任何情況下」「bounded by MAX_PUBLIC_SHELVES」「不做任何 KV 寫入」）。撰寫安全宣稱時的通病：把「本修正的目標情境」寫成「所有情境」。
- **G3**：tester 無法對未提交的 working tree 做 mutation check（HEAD 無「修正前」版本）——以「同種子只差一欄」的 200/404 對照替代,證據力足夠但值得記住這個替代技法。
