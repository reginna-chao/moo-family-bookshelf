## 2. 卡點與摩擦

- **G1 — 併發雙套件引發 flaky 失敗**：orchestrator 的全量 extension 測試與 reviewer 自行重跑的同一套件同時執行（reviewer 依 code-cycle 指引與驗證腿並行派出），CPU 爭用觸發 test.md 已記載的 findBy\* flake，額外花 2 次診斷重跑（~12 分鐘）才定案非缺陷。三次乾淨跑全綠。
- **G2 — pipe 遮蔽 exit code，兩次**：`pnpm test 2>&1 | tail` 與 `| grep` 讓 ELIFECYCLE 失敗不中斷 `&&` 鏈；第一次是靠肉眼看到文字才發現，第二次 grep 只撈到名稱含 "failed" 的通過測試。最終以「輸出落檔 + `echo EXIT_CODE=$?`」才得到可判定訊號。
- **G3 — 生成檔被 prettier 重排混入 diff，兩度發生，根因已定位**：root `.prettierignore` 明確排除 `extension/public/manifest.json` 與 `extension/tests/e2e/fixtures/mock-readmoo.html`（生成檔，由 `sync-version.ts` / `verify-selectors.ts` 擁有），但 **Prettier v3 只在 cwd 尋找 `.prettierignore`、不會向上層目錄找**——agent 從 `extension/` cwd 執行 `npx prettier --write` 時 root 排除完全失效（已驗證：`cd extension && npx prettier --check public/manifest.json tests/e2e/fixtures/mock-readmoo.html` 今日即 FAIL）。第一次由 security-auditor INFO-4 攔到，restore 後在 tester 第二輪期間又重演，才追到根因。commit 前二度 restore 收斂；持久修正已另開 task chip（見 L-3）。
- **G4 — 任務前提引用未合併的 sibling 產物**：任務描述以 `shared/src/api/safeErrorText.ts` 為既存參考，實際上 `fix/safe-backend-text` 尚未 commit（掛在另一 worktree 的未提交狀態）。以唯讀方式借閱 sibling worktree 取模式錨點、不建立依賴，並選擇零元件改動的設計避開檔案重疊，未造成返工。
