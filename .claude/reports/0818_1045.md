## 2. 卡點與摩擦

- **U1**（verbatim）：「我不確定要怎麼測試才對」——verify-before-test 第 1 輪，使用者直接測**已部署的 dev 站**（改動只在本地 worktree），且把 PWA 網址誤當 `@host` 的 API 位址。第一次的驗證指示只給了 `pnpm dev`，沒講「線上環境沒有這次改動」也沒給可複製的完整測試 URL。第二輪補上 `pnpm dev:remote` + 三條完整 localhost URL 後一次通過。
- **U2**（verbatim）：「請問現在的狀況是?」——Phase 1 收尾時文字寫了「把抉擇放在下面的選項元件裡」卻**沒有實際呼叫 AskUserQuestion** 就結束回合，使用者隔天需要主動追問狀態。承諾了工具呼叫就必須在同回合做完。
- **U3**（verbatim）：「請問目前狀況可以提交了嗎？」——rebase 進行到一半（stash apply 後衝突未解）回合被中斷，使用者需要追問。長 run 的中斷點落在「工作做一半」時，恢復後應先主動報進度。
- **G1**：同 U1，1 次 gate 重試。
- **G2**：coder（初版 dispatch）把 `docs/architecture.md` 的編輯**誤寫到主 checkout**，自行以反向 Edit 還原、orchestrator 複查主 checkout 乾淨。根因：agent 環境把主 checkout 列為 additional working directory。後續所有 dispatch prompt 加上「每次寫入前先確認路徑以 worktree 絕對路徑開頭」後未再發生。
- **G3**：工作期間 origin/main 前進 4 commits，其中 #118/#119 與本分支重疊 4 檔。到 Phase 6 security-auditor 掃描時才**偶然**發現（auditor 主動比對 origin/main），rebase 成本：2 個文件衝突、1 個語意跟進（consent 畫面依 #118 規則改 `variant="verify"`）、2 個額外 dispatch。若在 Fix Cycle 出口就 `git fetch` 檢查一次，語意跟進可併入 R2 的 coder dispatch。
- **G4**：R2 SUGGESTION 決策的 AskUserQuestion 未獲回覆（使用者離開），以文字 Stop Block 重新呈現後獲文字回覆。無重工，僅一次來回。
- **G5**：Windows Bash 預設 2 分鐘 timeout 殺掉一次串鏈驗證（typecheck+lint+test 串在同一個呼叫）；拆開後無事。

## 3. 改進提案

### Flow-structural（L#）

- **L0818_1045-1**：`target=.claude/skills/develop/references/code-cycle.md`（Phase 3 verify-before-test gate）| sketch=web/PWA 改動的驗證指示必須明說「改動只在本地，已部署環境沒有」，並給可直接複製的本地 URL 與啟動指令 | status=proposed（證據：U1/G1 燒掉一整輪 gate）
- **L0818_1045-2**：`target=.claude/skills/develop/references/code-cycle.md`（Phase 0 第 6 點 worktree 條款）| sketch=worktree 任務的 agent prompt 除了聲明邊界，還須要求「每次 Read/Edit/Write 前確認路徑前綴」；本 run 證實只聲明邊界不足以防呆（G2），加上逐次檢查措辭後零復發 | status=proposed
- **L0818_1045-3**：`target=.claude/skills/develop/references/code-cycle.md`（Phase 4 出口或 Phase 6 開頭）| sketch=進 security scan 前 `git fetch origin` 並檢查 `HEAD..origin/main` 是否觸及本次改動的檔案；跨日 run 的上游漂移應在 Fix Cycle 尚可併單時發現，而非 commit gate 前才撞上（G3） | status=proposed

### 執行槓桿（E#，無 flow 缺口）

- **E1**：Windows 上的驗證命令拆成獨立 Bash 呼叫（typecheck／lint／test 各一），避免 2 分鐘預設 timeout 截斷（G5）。
- **E2**：reviewer 處方 ≤5 行且逐字可套時，聚成單一 coder dispatch + orchestrator 自核 diff（R2 實作，全程零額外複審輪）——維持此作法。
- **E3**：緊接在 agent 已回報完整套件數字之後，orchestrator 不必再自跑一次全套件；一輪收尾跑一次確認即可。本 run 有約 2 次冗餘全套件執行。
