## 卡點與摩擦

**使用者的修正**

- **U1**「這個是其它 AI 分析的建議」：第一輪決策後貼了另一份分析，指出我對殘留 token 說得太輕（我寫「短暫」「重試一次就結束」），並點出索引列舉吞錯與回應遺失。查證後第 3、4 點屬實，計畫因此擴大。
- **U2**「這次一起做」：回應遺失原本我建議另開 issue，使用者選一起做，run 從單一 scope 變成跨三個 package。
- **U3**「暫不接受此競態為永久殘餘風險。請先加入可控制執行順序的重現測試……不可只增加入口的「刪除中」檢查就視為完成。」：我兩度把並行寫入列為「建議接受」，第二次才附上正確描述。這條決定把競態拆成 #468，並多了重現測試。

**關卡與重工**

- **G1** 我的分析有四句沒有依據，都是被別人抓到才更正：「短暫」（使用者貼的分析）、「保護會擋下靜默加入後顯示失敗」（自己重讀 `selfDeparture` 發現）、「改動未惡化」與「階段間隔只有毫秒」（design-critic Round 2）。第二次接受決定是建立在後兩句上，必須請使用者重新確認。
- **G2** 驗收 5 寫了不可能變綠的條件（更新後用原 token 重試），三位金魚全部回報，代表我在寫驗收時沒有走過 `readPresentedAuth`。
- **G3** R4「能力不超過任何知道 userId 的人」在帳號重建後不成立，到 security-auditor 才被證偽；修法把標記提前到 `auth:` 之前，等於 GO 之後又改一次順序（S2）。
- **G4** 我自己寫進計畫的管理者步驟（憑 Email 清 `verify:`）是一條接管路徑（W1），和 `worker/DEPLOY.md` 既有規則衝突，寫計畫時沒有 grep 該文件。Phase 6 的 operator procedure 規則有擋到，這條規則有效。
- **G5** 基準前進兩次。第二次的 #469 改了公開讀取，讓重現測試的 2 個案例失效，也改變了 #468 的嚴重度。文件表格因 Prettier 重排整段衝突，`git apply --3way` 無法解，要保留上游再手動補列，recipe 只涵蓋 `CHANGELOG.md` 與 `frontend.md`。
- **G6** tester、reviewer、security-auditor 類型在 run 中途從 registry 消失（之後又回來），改走 general-purpose 備案；`SKILL.md` §3 的備案指示可直接照做，沒有卡住。
- **G7** 第一次 `gh` 用猜的 `GH_CONFIG_DIR` 路徑失敗，要先讀 `settings.local.json`；之後還撞到一次 rate limit 提示。

## 改進提案

**Flow-structural**

- **L1106_1149-1**：`target=.claude/skills/develop/references/code-cycle.md | sketch=Plan completeness self-check 加一條：風險表裡描述時間或影響的詞（短暫、毫秒、未惡化、不超過…）要附 file:line、量測或「未驗證」，否則不能當作請使用者接受的依據 | status=proposed`
- **L1106_1149-2**：`target=.claude/skills/develop/references/code-cycle.md | sketch=Credential invalidation 一項補上：把「殘留 token 能做什麼」當驗收前，逐一列出帶 token 就能寫入或鑄 token 的路由（refresh 兩種 body、PUT verify、verify/otp、qr-token），並考慮帳號重建之後的情況 | status=proposed`
- **L1106_1149-3**：`target=.claude/skills/develop/references/code-cycle.md | sketch=Updating uncommitted work onto a moved main 的第 2 條擴及 docs/architecture.md 與 backend.md：Prettier 重排的表格衝突時保留上游、重新插入本次的列，再跑 prettier | status=proposed`
- **L1106_1149-4**：`target=.claude/skills/develop/references/code-cycle.md | sketch=Base re-check 補一句：釘住現況的重現測試要在每次基準更新後重跑，因為 main 上的修正可能改變它描述的嚴重度 | status=proposed`
- 不提升：`Phase 6` 的 operator procedure 掃描與 `SKILL.md` §3 的角色備案，這次都如預期運作，不需修改。

**執行槓桿**

- **E1106_1149-1**：寫驗收前，先用 `app.request` 的 scratch 腳本把最關鍵的半完成狀態跑一次，能提早抓到 G2 這類不可能的條件，成本遠低於金魚一輪。
- **E1106_1149-2**：貼上的外部分析先逐點查 `file:line` 再回覆，這次這樣做找到兩個真缺口，也發現其中一句要更正自己的說法。
- **E1106_1149-3**：`GH_CONFIG_DIR` 先從 `.claude/settings.local.json` 讀，不要猜路徑。
