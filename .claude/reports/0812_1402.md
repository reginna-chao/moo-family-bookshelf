## 2. 卡點與摩擦

- **G1 — reviewer 派遣死於 API session limit**:第 1 輪 reviewer 首次派遣回傳「You've hit your session limit · resets 12:30pm」,零產出。依 SKILL.md §3 重派全新 agent 成功。證據:對話中 Agent 錯誤回傳與其後的重派。無流程缺口(規則已涵蓋),但成本為一整段等待與使用者兩次手動接續(「Continue from where you left off」「Try again」)。
- **G2 — origin/main 在 run 中前進**:Phase 0 fetch 時基底為 `d456a8d`,第 1 輪 reviewer 以 O5 指出 `origin/main` 已前進至 `8ff9b60`(#100)。orchestrator 於 fix round 後補 `git fetch && git merge --ff-only` 並重跑全套驗證。code-cycle 只在 Phase 0 fetch 一次,長 run 必然過期。
- **G3 — orchestrator 註解編輯觸發 prettier 紅燈**:第 2 輪套用註解修正後,`prettier --check` 對 `publicShelfService.test.ts` 報格式問題,多跑一輪 `--write` + 重驗。agent 產出都有跑 prettier,orchestrator 手改沒有。

## 3. 改進提案

- **L0812_1402-1** `target=.claude/rules/test.md | sketch=Anti-Drift 增列:新增「測試基礎設施 guard / tripwire」時,須以一次性 mutation test(暫時退化 production 目標、確認紅燈、還原)證明其真的會攔截目標回歸 | status=proposed`
  本 run 的 mutation test(sed 退化 `publicShelf.ts` floor → 3 紅 → 還原)是 tripwire 有效性的唯一實證;tester 自陳「wiring is argued, not executed」。
- **L0812_1402-2** `target=.claude/skills/develop/references/code-cycle.md | sketch=Phase 8 commit gate 前補一步:重新 fetch origin,若 main 前進則 ff/rebase 後重跑該 scope 全套驗證 | status=proposed`
  G2 證據;本 run 靠 reviewer 順帶發現,不該依賴審查者兼差做分支狀態檢查。
- **L0812_1402-3** `target=.claude/agents/reviewer.md | sketch=增列:當變更宣稱「鏡射/相容某平台行為」時,對照 node_modules 內已安裝模擬器(如 miniflare)的原始碼驗證,不憑記憶 | status=proposed`
  本 run reviewer 兩度以 miniflare 原始碼(`namespace.worker.js` parseInt 先於下限檢查、0/負數/NaN 短路訊息)推翻註解過度宣稱——高價值行為,目前無規則保證下次重現。

- **E1(執行槓桿)**:orchestrator 手改任何 comment/doc 後,立即對該檔跑 `prettier --check`,不要等最終驗證(G3 成本一輪重跑)。
- **E2(執行槓桿)**:自主(非互動)session 中,互動 gate(需求確認、verify-before-test、SUGGESTION 決策)以 TL 判斷放行時,期末報告須逐項揭露處置與理由——本 run 已如此執行,列為慣例以便下次直接沿用。
