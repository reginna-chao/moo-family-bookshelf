## 2. 卡點與摩擦

- **G1**：4 次 agent 死亡，全部集中在長時間 leg 的尾段。與前次 run 不同的是：3 個 tester 死亡時**編輯皆已落盤**且有 RENAME HANDOFF 當規格，orchestrator 直接自跑四包驗證 + grep 對照 handoff 清單即可收斂——省下 2~3 次全新重派（每次 ~15-18 萬 tokens）。§3「必須全新重派」的規則在「只剩驗證」情境下過於昂貴。
- **G2**：main 高頻推進（本 run 期間 +9 commits，多為其他 session 的 worker 修補）。這次紀律有守住：PR 前 rebase、CHANGELOG 條目在 rebase 之後才追加，未重演 PR #103 的衝突-CI-不觸發事故。
- **G3**：reviewer「實測重現」的價值再次得證——S1/S2 兩個競態若只做靜態審查很可能被當成理論風險跳過；reviewer 用 scratch 測試證實後,修與不修的決策毫無爭議。
- **G4**：R1 落地 reviewer 對 S2 的處方後,R2 的 re-review 才發現處方只蓋了「排隊前置」半邊、漏了「in-flight 失敗」半邊——處方本身也需要對稱性檢查（成功/失敗/排隊/在途四象限）。
