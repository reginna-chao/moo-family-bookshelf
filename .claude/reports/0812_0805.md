## 2. 卡點與摩擦

- **U1**:「keep on」— session limit 中斷後的續跑指示(非需求修正;本 run 無任何需求面修正)。
- **G1**:3 次 agent dispatch 死於 API 錯誤(stall / session limit / connection closed),損失約 154k subagent tokens 與 ~27 分鐘 wall-clock。第 3 次 reviewer 重派時在 prompt 加上「tight, targeted pass + 明確 4 點 checklist」,257s 完成——收斂 prompt 是有效解。
- **G2**:Phase 0 preflight 只檢查 `origin/main..HEAD`(ahead),未檢查 `HEAD..origin/main`(behind)。worktree 落後 origin/main 2 個 commit,由 security-auditor 事後發現,需補 fast-forward 並重跑全部 lint 驗證(新進 worker 測試檔需重新確認零 warning)。
- **G3**:任務前提「worker routes override(`reportUnusedDisableDirectives: "error"`)已存在」實為未合併分支 `chore/enforce-route-layering-lint` 的內容,不在 origin/main。前提未驗證即寫入前兩個 agent prompt,由 audit 證偽後才修正(對本 diff 無實害:本次不碰任何 eslint config)。
- **G4**(執行面小摩擦):並行 Bash 呼叫共享 cwd,兩次 shared 套件的指令(基線 lint、毒丸)因 cwd 不確定而空跑/誤跑,各需補一次明確 `cd` 重跑。

## 3. 改進提案

- **L0812_0805-1**:`target=.claude/skills/develop/references/code-cycle.md | sketch=Phase 0 isolation check 除 ahead(origin/main..HEAD)外必須同時檢查 behind(HEAD..origin/main),落後即先 fast-forward 再進 Phase 1 | status=proposed`
- **E1**:任務書中描述 repo 狀態的前提(某 config 存在、某旗標已設)在寫入 agent prompt 前先花 30 秒 grep 驗證,避免錯誤前提擴散到多個 dispatch。
- **E2**:agent 死於 API 錯誤後重派時,同步收斂 prompt(明確 checklist + 「focused pass」約束)——縮短單次 run 時長本身就降低再次死亡的機率。
- **E3**:並行 Bash 呼叫每一條都要自帶明確 `cd <absolute path>`,不可依賴 cwd 延續(本 run 兩次因此空跑)。
