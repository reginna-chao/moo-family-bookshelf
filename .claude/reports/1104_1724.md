## 2. 卡點與摩擦

- **U1**：「為什麼這題你是建議不加?」問的是我建議不補送失敗儲存的理由。追查後，我列的第二個理由（消耗靜默 join 額度）說過頭了：`auth-refresh.ts:213`、`:219` 大多會擋下。我在沒查過就寫成事實，使用者一問才更正。
- **G1**：我在決策關卡寫「離開時正常存下」，使用者據此選了方案。實際上 `worker/src/routes/family.ts:650` 離開時會撤銷 token，那筆 PUT 回 401。安全掃描與 reviewer 才發現，事後向使用者更正。
- **G2**：更正時又寫成「三條路徑都 401」，第二輪 reviewer 的 Worker 探針找到例外（`MEMBER_NOT_FOUND`／`FAMILY_NOT_FOUND` 而 token 仍有效）。同一個事實錯兩次，兩次都沒有在寫下前跑 Worker。
- **G3**：計畫把 `useFamilyDataEffects.ts` 列為同一空檔、已被順序修正涵蓋。`flushSync` 只保護 effect 當下發出的請求，`await refreshMembers()` 之後的接續沒有擋到，這就是 S1（被移除成員打開 Dialog 就會觸發，不用搶時間）。
- **G4**：預測 25 行，量到 41 行，超過上限 1 行。多的是新檔的 JSDoc。計畫裡的 helper 只算了函式本體。
- **G5**：這張是 P0 隱私問題，機械條件卻判為 fix mode。多虧超過 1 行才升級，手動驗證與安全掃描都跑了。S1、S2 是這次擴大審查才進到這個 PR；W1 是安全掃描才發現的。fix mode 下 SUGGESTION 只會開 issue，這兩條洩漏就不會在這張修掉。
