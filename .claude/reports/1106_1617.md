## 2. 卡點與摩擦

- **U1**：使用者不接受 TL 建議的「維持現狀」，原話：「請將『限制 PIN 猜測』與『本人收回帳號控制權』一起設計。」我把一個設計問題當成單純的取捨提問，第 4 項因此重新設計。
- **U2**：「DO 如果會增加費用請幫我強調」。選項裡只寫了技術代價，沒有寫費用。
- **U3**：使用者中斷問題並問「請問現在狀況是?」。當時連續多輪都是背景等待，訊息很短，看不出整體進度。
- **G1**：我給了「本人可以靠救援回來」的前提，使用者據此做了決定。金魚讀程式發現單人家庭不成立，決定要重問。
- **G2**：TL 建議「不做硬上限」所依據的推算沒有實測，實測後超過停止門檻，又重問一次。
- **G3**：救援文件在金魚兩輪、reviewer 兩輪、auditor 兩輪裡持續被找到問題，後段都是操作步驟與文件。使用者選擇在第三輪文件修正後停止複審。
- **G4**：`node -e` 就地改檔沒有落地，靠事後 `grep -c` 才發現；tester 的 shell 指令留下一個空的怪檔；含引號的 heredoc 在 Bash 工具失敗。三者都浪費了一輪。
- **G5**：`main` 在 run 期間前進 3 次，其中 2 次和本 run 的 `CHANGELOG.md`、`docs/architecture.md` 重疊，要做 WIP commit + rebase。
