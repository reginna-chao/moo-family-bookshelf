## 2. 卡點與摩擦

- **U1**（使用者，決定關卡）：「為什麼不推薦升級成完整流程?」— 我預測 fix mode 成立就直接推薦 fix mode，沒把 issue 的「完成條件」列了兩個要釘住的行為納入推薦。重新評估後改推薦完整流程，多一輪需求確認。證據：第一批 AskUserQuestion 的回答。
- **G1**（派工失敗）：第一個 coder 在使用者選「另開新 worktree」之後被桌面 app 的 worktree 守門擋下，無法寫入新開的 worktree，run 中止。使用者選擇「停在這裡，去新 worktree 開 session」；後來 #371 合併、規則改為「app worktree 裡不提供另開 worktree」，才在原 worktree 續跑。證據：coder 第一次回報「Blocked: I couldn't write to the worktree you assigned」。
- **U2**（使用者，流程疑問）：「為什麼 worktree 是開始後才問? 不是寫計畫前詢問?」與「選項中出現留在此 worktree，但我看選項的時候根本不曉得這個 worktree 是哪個」— 兩者已在 #371 落地為規則（決定關卡在計畫前；選項標籤帶資料夾名）。不另提案。
- **G2**（續跑）：#371 合併後續跑時，計畫只存在對話裡，靠這個 session 還活著才接得上；若 session 已結束，就是 #371 要解決的情境。這次 PLAN.md 是在 GO 之後、續跑時才補寫（規則當時才剛合併），之後的 run 應在 GO 當下寫。
