## 2. 卡點與摩擦

- **G1 前提不成立**：issue #275 寫「Dialog 已會擋下帳號不符」，但開工時 #271 還沒進 main，修正只存在另一個 worktree 的 WIP 分支。Phase 0 的 premise check 抓到，run 停下來等 #271 合併。
- **G2 範圍來回三次**：使用者在需求確認選了「Dialog 也改用 cookie」（省掉切頁與 2 次多餘請求）。安全掃描指出 cookie 相符會放行同步書單 → 加一輪「同步前用 `#/me` 複查」→ re-review 指出 cookie 相符仍可產生 PWA 登入 QR Code、離開家庭 → 整個 Dialog 部分還原成 main。第 2 輪的 coder（680 秒）與 tester 全部作廢。
  - 根因：Phase 1 的風險分析只寫了「cookie 是頁面可寫的，沒有多出攻擊面」，沒有比較「cookie 的可寫入範圍」與「`#/me` DOM 的可寫入範圍」，也沒有列出 Dialog 的 `match` 會放行哪些寫入。這兩件事在需求階段就查得到。
- **G3 orchestrator 的錯誤轉述**：第 2 輪 coder 回報「cookie 確認時仍可做的非同步寫入，與 #271 的 `unknown` 相同」，orchestrator 原樣轉述給使用者。reviewer 才指出兩者不同：`unknown` 是沒人被判定成別人，cookie 指錯人是確定地放行。
- **G4 對外文字衝突到 coder 回報才出現**：隱私政策與 `extension/README.md` 寫「不使用／不讀取 Cookie」。這是需求階段 grep 一次 `cookie` 就能發現的事，卻等到第一個 coder 做完才浮現，多一次 gate。
- **G5 手動驗證的版本不是最終版本**：使用者驗的是 Dialog 也讀 cookie 的版本；之後範圍收斂，「開 Dialog 不切頁」不再成立。紅點程式沒變，但完成報告必須特別提醒重驗。
- **U1 使用者中斷**：第 2 輪 coder 前景執行約數分鐘時被中斷，使用者問「請問目前狀況?」。前景長時間 dispatch 期間使用者看不到進度。之後的 dispatch 改為背景執行。
- **G6 worktree 內 gh 找不到帳號**：第一次 `gh issue view` 用錯 `GH_CONFIG_DIR` 路徑（`~/.config/gh-personal`），讀了記憶檔才改成 `%AppData%\gh-personal`；PowerShell 下指令無輸出，改用 Bash 才成功。
