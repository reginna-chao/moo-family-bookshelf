## 2. 卡點與摩擦

沒有使用者更正（U# 為 0）。以下都是 G#。

- **G1 — orchestrator 的初始分析把因果鏈判斷錯了，並在決定關卡當成事實呈現。** 我讀到 `useOnboardingAttempts.ts:48` 會設 `"recovering"`、`useRecoveryVerificationBridge.ts:85` 會設回 `"verify-prompt"`，就推論「PIN 輸錯 → 輸入框重新掛載」。實際上已設 PIN 的帳號走的是 `useOnboardingStartFlow.ts:113` 的另一個 `run`，錯的 PIN 在 `:53-58` 就 return，碰不到 `:70`。我是從 setter 往回找呼叫點，沒有從使用者動作往前、依帳號類型、連同伺服器回應（`worker/src/routes/auth.ts:139-156`）走完一次。代價：第一輪決定關卡的 4 題裡有 2 題的選項建立在錯的前提上，計畫整份重寫，多一輪金魚重審與 2 次使用者提問。
- **G2 — 金魚 Round 1 兩位各自獨立抓到 G1。** 兩份報告都指向同一段程式碼，orchestrator 讀碼後確認成立。這是本次 run 裡隔離審查最有價值的一次。
- **G3 — 重寫後的 E2E 情境仍有 Blocker，由 Round 2 抓到。** 「模擬新裝置」只清 `chrome.storage.local`；familyId 也寫在 `chrome.storage.sync`，沒有 local userId 時會被讀回（`extension/src/storage/familyId.ts:17-28`）。repo 裡已有現成的清法（`extension/tests/e2e/helpers/mock-server.ts:42-47`、`dialog-state-machine.spec.ts:60-68`），我寫計畫時沒有先 grep。
- **G4 — orchestrator 在 coder prompt 裡逐字指定的 CHANGELOG 句子不屬實。** 原句對「圖形」宣稱「不必先點一下」，但 `PatternLock` 沒有任何鍵盤操作，讀者感覺不到。reviewer 抓到，改成只講 PIN。coder 照字貼上，speak-human-tw 只看語感，兩者都不會攔這種事實問題。
- **G5 — 前段分析期間長時間沒有對使用者輸出。** 讀碼、查 advisory、比對呼叫點的階段連續多次工具呼叫，沒有進度說明，系統多次提醒。
- **G6 — E2E「修正前為紅」只能就地改 production 檔。** `test.md` 的 Anti-Drift 規則寫「Mutate a copy, never the shared production file in place」，但 E2E 載入的是 build 出來的 `dist/`，複本等於另一份 checkout 加安裝。這次在計畫裡明訂例外（無 agent 執行、production 已 stage、`git restore` 後 `git diff --quiet`），金魚 Round 1 也指出規則本身沒有這個例外。

## 3. 改進提案

### Flow-structural

- **L1111_0324-1**：`target=.claude/skills/develop/references/code-cycle.md`（Phase 1 step 2「Your OWN premises count too」或 step 3 bug intake）｜`sketch=` 一條「A 之後 B 會發生」的因果鏈，必須從使用者動作往前走到底，依帳號類型分開走，並包含決定分支的伺服器回應；從 state setter 往回 grep 到的呼叫點只是線索，進決定關卡前要標成未驗證｜`status=proposed`
- **L1111_0324-2**：`target=.claude/rules/test.md`（E2E tooling 或 Anti-Drift）｜`sketch=` E2E 要把擴充功能重設成「全新裝置」時，`chrome.storage.local` 與 `chrome.storage.sync` 都要清且要 await，指向 `CLEAR_STORAGE_SCRIPT`；只清 local 時 `readFamilyId` 會從 sync 讀回 familyId｜`status=proposed`
- **L1111_0324-3**：`target=.claude/rules/test.md`（Anti-Drift →「Guard tests must prove they can fail」）｜`sketch=` 補上 E2E 的做法：E2E 的反證可以就地改 production 檔，條件是沒有 agent 在執行、該檔已 stage、還原後 `git diff --quiet` 為 0、最後重跑 `pnpm build`；目前規則只有「mutate a copy」，E2E 做不到｜`status=proposed`
- **L1111_0324-4**：`target=.claude/skills/develop/SKILL.md`（§3，CHANGELOG bullet 的 owner 段）｜`sketch=` orchestrator 在 prompt 裡逐字指定 bullet 時，先逐一確認句中每個名詞對讀者都有可觀察的效果；或改成只給事實、讓 coder 寫句子｜`status=proposed`

### 執行槓桿（no flow gap）

- **E1**：分析階段每完成一個可以講的結論（「四個流程已修」「找到一條候選路徑」）就輸出一行，不要等整段分析結束。
- **E2**：寫 E2E 步驟前，先 grep 同一個測試目錄裡有沒有做過同樣事情的 helper（這次是清 storage），計畫直接引用它。
