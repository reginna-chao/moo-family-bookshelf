## 2 卡點與摩擦

- **U1 —「這是在哪個 worktree 進行?」**：verify-before-test 的說明只寫了相對路徑 `.claude/worktrees/issue-250-7a8ff0`，沒有寫絕對路徑和分支名稱，使用者要再問一次才能確定在哪裡執行。
- **U2 —「我在 issue-250-7a8ff0 資料夾開 pnpm dev，pwa local port 是多少?」**：說明裡寫「`pnpm dev` 的 info 輸出會列出 PWA 網址」，這句話是錯的。`scripts/dev-info.mjs` 只印 API endpoint，不印 PWA 網址。code-cycle Phase 3 step 3 要求給出 local URL，我沒有先查就寫了。
- **G1 — worktree 缺少被 gitignore 的本機設定，差點讓使用者對正式環境做測試**：回答 U2 時才發現 worktree 沒有 `.env` 和 `worker/.dev.vars`（只有主 checkout 有）。沒有 `.env` 時 `pwa/src/constants.ts:22-25` 會退回正式伺服器的網址，使用者照原本的說明跑 `pnpm dev`，切換的分享設定會寫進正式資料。這個檢查應該在寫驗證說明之前做。
- **G2 — orchestrator 在 coder 回來時就看到的問題，延後到 reviewer 才處理，多跑了一整輪**：第 1 次 coder 回來後，我已經注意到「儲存成功後還有待儲存變更，按鈕卻顯示『已儲存』」（`extension/src/dialog/FloatingActionBar.tsx:27`），在驗證說明裡寫成「交給 reviewer 判斷」。reviewer 判成 CRITICAL（C1）。如果當下就依 code-cycle 的 In-round adjudication 派回 coder，可以省掉第 2 輪的 coder、tester、reviewer、security-auditor 共 4 次 dispatch，使用者手動驗證的也會是最終版本。現在 C1 和 S1 的修正只有自動測試驗證過。
- **G3 — 資安掃描和第 1 輪審查平行跑，Fix Cycle 之後要補掃一次**：這是 code-cycle Phase 3 step 4 明寫的代價（1 次 dispatch、79 秒），而且第 1 次掃描獨立找到了 S1，和 reviewer 互相印證。記錄下來，不算缺口。
- **G4 — security-auditor 把已有 issue 的問題當成新的 P0 回報**：它建議開的「同步和儲存互相覆蓋」就是現有的 #249。我在開 issue 前用 `gh issue list` 比對才擋下來。第 2 次掃描的 prompt 有列出「已記錄、不要重報」的 issue（#249、#256），就沒有再發生。
- **G5 — tester 的突變檢查在測試目錄留下暫存檔，被同時執行的 auditor 看到**：第 1 次 tester 建了 `extension/tests/unit/dialog/zzMutation250.test.ts`，第 2 次把舊版正式檔複製到 `tests/component/` 底下。兩次都有清乾淨、沒有動到正式檔（比 0924_1406 的 G3 好），但暫存檔仍放在共用 worktree 裡。
- **G6 — issue 引用的行號已經過期**：#250 寫的 `:261`、`:272` 是 #236 合併前的位置。Phase 0 的 premise check 有抓到，coder prompt 用的是重新確認過的行號。
