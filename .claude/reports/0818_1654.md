## 2 卡點與摩擦

**U#（使用者更正）：無。** 三次 AskUserQuestion（方案、採納範圍+S7、retro+commit）皆一次定案。

**G1 — 交派給 tester 的路由表含兩處錯誤（orchestrator 轉錄失誤）**
coder 回報後 orchestrator 手寫端點表交給 tester，把 `PATCH /:id/member/:uid` 寫成 `PUT …/settings`、`PUT /:id/transfer` 寫成 `POST …/transfer-ownership`。tester 因 prompt 內建的「以原始碼為準，不信表格」指示而自行核對原始碼，未造成產出錯誤——但這是靠下游防線接住，不是上游正確。轉錄 route 資訊時應直接引用 `createRoute` 定義的 method+path 原文。

**G2 — reviewer 與 auditor 對同一事實各自花費完整查證（部分重工）**
兩者平行派送、互不知情，S1（註解低估寫入扇出）與「self-leave 共用額度」「前端英文 429 訊息」三個發現完全重疊。平行的代價是重複查證；換得的是獨立性（兩個 agent 用不同方法得到相同結論，對 PASS 的信心實質加分）。此為刻意取捨，記錄非提案。

**G3 — auditor 的 WARNING 與本 diff 無關但極有價值**
「被移除成員靜默重加入」是產品級既有漏洞，靠 Dimension 8 的 blast-radius 掃描抓到（diff 只是碰了 removeMember）。mode: changed 沒有把視野縮到只看 diff 行，這正是它應有的行為——維持現狀。

## 3 改進提案

### Flow-structural

- **L0818_1654-1** — orchestrator 在 agent prompt 中轉錄 API 路由 / schema / 常數時，必須直接貼上原始碼中的定義原文（`createRoute` 的 method+path、常數宣告），不得憑 handler 名稱或記憶改寫；已轉寫的表格一律附「以原始碼為準」的免責指示（本 run 靠這句自救）。
  `target=.claude/skills/develop/references/code-cycle.md | sketch=agent-dispatch 段加一條：quote source definitions verbatim in prompts, never paraphrase routes/schemas | status=proposed`
  （與 L0817_1614-1「引用的具體事實先驗證」同族——跨報告重現，/distill 時應合併為一條）

### 執行槓桿（E#，無流程缺口）

- **E1** — security-auditor 對「宣稱的防護」逐條執行攻擊探針（本 run 六條全試）比敘述式審查有實質增量：兩個 INFO 級 trade-off 都是探針量測出來的（100/100 並發放行、429 路徑零 KV 寫入）。invariant-類變更值得固定押 auditor。
- **E2** — reviewer 處方被超出時（S3 折疊+factory 重構），focused delta re-review 的成本（~7 分鐘）換到「從 git object store 復原舊 blob 逐行比對」級別的無回歸證明，值得。
- **E3** — spawn_task chip 是安置「範圍外但真實」發現的正確出口（本 run 兩張：靜默重加入、429 在地化），比塞進當前 PR 或只寫在回覆裡都好。

## 4 Skill / Agent 增減建議

- **不新增任何 agent。** 本 run 四角色首次全數登場且分工乾淨：coder 落地含兩個有依據的 placement 微調、tester 兩輪皆附「防自我實現」思考、reviewer 主審抓到 7 項含跨檔清單失準、auditor 用可執行探針取代敘述。
- **auditor 的「攻擊探針寫在 scratchpad、絕不進 repo」紀律值得固化**——`git status` 全程乾淨。/distill 時評估寫進 `.claude/agents/security-auditor.md`。
- **無可精簡項。**
