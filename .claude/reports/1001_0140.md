## 2. 卡點與摩擦

- **G1**：第一次派出的 coder 因 `401 OAuth access token has expired` 中途死亡，使用者回「keep on」後才繼續。
  - 證據：留下 3 個檔案的改動（共用函式、兩端 `aria-label`），缺 CHANGELOG。依 SKILL.md §3 的鑑識流程判定「改動完整且可機械驗證」，orchestrator 自己跑 lint／typecheck／prettier／EOL 後採用，只另派 coder 補 CHANGELOG，沒有整批重做。
- **G2**：fix mode 條件 3 的量測基準在「接續既有分支」時不明確。
  - 證據：這輪 production 只改 +22 / −6，但 `git merge-base origin/main HEAD` 會把同一分支上一輪已 commit 的改動（#235 本體）一起算進去，遠超 40 行，只能走 full cycle。`code-cycle.md` 條件 3 的說明寫「merge-base 只量本次 run 的工作，即使 run 接續既有分支」，但字面上的指令做不到這件事，兩者互相矛盾。
