## 2 卡點與摩擦

- **U#**：無使用者糾正。
- **G1 — issue 預設的方向（把 body 搬進 schema）在盤點後不成立**：16 個讀 body 的 handler 中有 10 個「先扣 per-user 次數、再解析 body」，搬進 schema 會改變計次語意與錯誤優先序；再加上大量依賴 KV／呼叫者的檢查、415 與 key strip 的副作用。這個結論要靠一次完整盤點才得出；先派 Explore 做廣域掃描、再做範圍決策，這個順序是對的，避免了開工後才發現要大改或回退。
- **G2 — 盤點時順帶找到真正的 bug**：公開書櫃 create／update 對 JSON `null` body 會丟 TypeError 變 500（`worker/src/routes/publicShelf.ts`）。這個 bug 與 issue 主題無關，是「逐一列出每個 handler 的 body 分類規則」這個要求順帶挖出來的。
- **G3 — sandbox 的 `node -e` 就地寫入被靜默丟棄**（tester 回報）：第一次 mutation check 用 `node -e` 改檔，結果沒寫進去，跑出來的綠燈無效；改用 Edit tool 重做才得到真正的紅燈。這是 memory 裡已記錄的 sandbox 怪癖，agent 端仍然踩到。
- **執行面良好之處**：tester 把測試用的 probe 路由掛到「正式的」`app` 上，而不是另建 synthetic app，讓整合測試真的走正式的 `onError` 和 middleware 鏈，mutation (a) 證實了這一點，也免去「測試裡複製一份 onError 並加同步註解」的漂移風險。
