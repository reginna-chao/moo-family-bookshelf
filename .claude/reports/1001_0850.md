## 2. 卡點與摩擦

- **U#**：無。使用者沒有糾正或打斷。
- **G1**：需求分析時 orchestrator 已經講到「CPU 成本，不建議開到 5MB」，卻沒有量測就推薦 2MB，並讓 CHANGELOG 寫出「大約 4000 本以內都可以」。後端 reviewer 在 Phase 4 用 Node 實測（4500 本約 17–25ms，免費方案每請求 10ms）才指出這個數字在免費方案上可能做不到，多出一輪 Fix Cycle 重寫 CHANGELOG、補 `docs/architecture.md` 的殘餘風險。這個風險在 Phase 1 就看得到，卻到 Phase 4 才處理。
- **G2**：orchestrator 在後端 coder 的 prompt 裡把「10001 筆最小書目約 160KB」寫成事實，coder 實測是 318,934 bytes（約 320KB）。結論沒變（仍低於 2MB），但這是把沒算過的數字當事實交給 agent。
- **G3**：verify-before-test 的實測腳本裡，600 本的資料只有約 252KB，剛好低於舊上限，那一列證明不了修正有效（靠 4000 本那列才成立）。issue 內文說「600 本真實長度的書目前會拿到 413」，這句話本身也沒有先執行確認就拿來當驗收條件。後來派 tester 時改成「測試內自己斷言 `Buffer.byteLength(body) > 262144`」才補上。
- **G4**：第一次啟動本機 `wrangler dev` 時加了 `--persist-to` 指向 `%TEMP%` 下的 8.3 短路徑，miniflare 的本機 Ratelimit binding 對每個請求都丟 internal error（全部 500）。拿掉 `--persist-to` 用預設狀態目錄後正常。只觀察到這一次，原因沒有進一步確認。
- **G5**：背景啟動的 `wrangler dev` 沒有對應的停止工具可直接用，兩次都靠查 8799 埠的行程再 `Stop-Process`，背景工作因此回報 exit code 255（不是真的失敗）。
- **G6**：前端 tester 做 mutation check 時暫時改了已暫存的 production 檔（`shared/src/personal/saveErrors.ts`），事後還原；後端 tester 則是用 `git archive HEAD` 匯出舊版到暫存目錄跑，完全沒碰 worktree 的 production 檔。兩種做法都符合 `.claude/rules/test.md`，後者不需要事後用 diff 驗證還原。

## 3. 改進提案

### Flow-structural

- **L1001_0850-1** `target=.claude/skills/develop/references/code-cycle.md`（Phase 1 步驟 6 的 Performance concerns）| sketch=需求要放寬容量上限（body 大小、筆數上限）時，Phase 1 就先量一次該上限下的處理成本（Worker 端 JSON.parse／驗證／stringify 的 CPU 時間）並對照免費方案的 10ms；沒量過的容量數字不得進 CHANGELOG 或 UI 文案，只能寫進殘餘風險 | status=proposed
- **L1001_0850-2** `target=.claude/rules/backend.md`（Local-dev facts）| sketch=`wrangler dev --persist-to` 指向 `%TEMP%` 的 8.3 短路徑時，本機 Ratelimit binding 每個請求都 internal error；用預設狀態目錄即可（單次觀察，原因未確認）| status=proposed
- **L1001_0850-3** `target=.claude/skills/develop/references/code-cycle.md`（Phase 3 步驟 3 verify-before-test）| sketch=用來證明「大小上限已放寬」的實測資料，腳本要自己印出並比對位元組數是否真的超過舊上限，否則那一列不算證據 | status=proposed
- **L1001_0850-4** 不提升：G6 的兩種 mutation 做法 `.claude/rules/test.md` 已經都允許，再加規定只是增加篇幅。

### 執行槓桿

- **E1**：寫進 agent prompt 的數字，只有兩種寫法：實際算過的，或明講「未驗證的估計」。這次的「約 160KB」屬於後者卻寫成前者（`code-cycle.md` Phase 1 步驟 2 已有這條規則，這次沒照做）。
- **E2**：issue 內文給的驗收例子（「600 本會 413」）先用一行腳本算位元組數再採用。
- **E3**：背景啟動本機 Worker 之前，先把「怎麼停掉它」準備好（記下埠號對應的行程，或先載入停止背景工作的工具），不要等要停的時候才找。

## 4. Skill / Agent 增減建議

- 不建議增減。五個 agent 平行的那一批（tester ×2、reviewer ×2、security-auditor）沒有檔案衝突，總等待時間由最慢的後端 tester（424 秒）決定。
- reviewer 的 prompt 這次列了「請特別衡量的點」（guard 在 auth 之前、CPU、路徑比對），S1 正是從其中一點查出來的。這個寫法可以留在 orchestrator 的習慣裡，不需要改 agent 定義。
